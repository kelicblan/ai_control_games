# 模型存储修复与玩家远程配置持久化

2026-10-15 用户要求覆盖此前会话密钥设计：远程配置及密钥保存到当前玩家数据库，刷新后继续使用。

MiniMind 错误来自 Wllama 默认 CacheManager 构造时强制检测 OPFS，即使已经提供完整 Blob 也会失败。注入实际 SDK CacheManager 支持的内存 backend；权重缓存优先 CacheStorage，后备 IndexedDB，完整长度和 SHA-256 通过后原子提交。全部持久化接口被禁用时只使用内存，不将缓存不可用当作推理加载失败。

新增 SQLite remote_models 表，以玩家 cookie 身份和配置 ID 为联合主键。API Key 使用独立本地随机密钥 AES-256-GCM 加密，AAD 绑定玩家和配置；元数据接口不回传密钥。生成仅接受已保存配置 ID，由服务端解密转发。更换接口 origin 不自动沿用旧密钥。

验证：存储、模型客户端、延迟配置恢复、共享会话、世界客户端等 10 文件 33 项通过；代理、模型管理、对话及独立 SQLite/HTTP 服务等 10 文件 84 项通过，共 117 项。独立进程测试验证硬重启后配置保留及跨玩家隔离。生产构建、NPC 边界检查通过。

真实 Worker 浏览器测试 2 项通过：禁用 OPFS/CacheStorage 后 IndexedDB 写入及刷新缓存复用（同时阻断模型和清单网络）；禁用全部持久化存储后仍能加载和执行推理。远程生成受控 HTTP 503 后使用真实 MiniMind，原优先选择保留。远程提供商响应受控，不声称已连接真实付费服务。

首次刷新验证发现对话探测早于异步配置列表的问题，新增 prepareModels 等待启动发现完成，并由 model-catalog-startup 测试覆盖。工作区同时把通知移出设置弹窗，浏览器测试改为检查请求和保存按钮恢复可用。

在软件 WebGL 重建场景时，网络已返回配置但主线程长时间占用触发元数据读取超时，元数据请求期限延长为 60 秒（生成调用仍保持既有 5 秒服务端超时）。配置浏览器验收禁用 WebGL，以独立验证设置与 SQLite 流程；场景渲染不属于这项验收。

最终配置浏览器用例通过（18 秒）：真实数据库新增/编辑/删除、刷新后恢复优先模型、已保存密钥留空保留、生成请求不携带密钥。提供商响应受控。与上述 2 项真实 Worker 存储和 1 项故障回退合计 4 项浏览器场景通过。最终构建再次通过。

## 测试反馈与智谱兼容修复

用户反馈测试按钮无提示、远程模型不可用。设置弹窗恢复测试中/成功/失败的就地提示，优先模型面板显示具体错误，世界频道继续记录。浏览器用例新增受控 HTTP 401 的弹窗提示以及重试成功提示，最终通过（18.5 秒）。首次复测受其他工作并发重启 18081 干扰，最后使用独立 18092/remote-ui-qa.sqlite 服务验证并清理测试服务。

本机 open.bigmodel.cn 的系统 DNS、1.1.1.1 和 223.5.5.5 均被代理解析为 198.18.0.162。仅当域名的全部本机 DNS 结果为 198.18/15 时，通过固定 TLS DNS-over-HTTPS 再解析，重新校验并固定公网地址。保留内网/保留地址和混合 DNS 拒绝规则。实际公网解析为 47.74.41.78/47.245.63.126，未认证探测得到预期 401。GLM-5 系列测试输出预算提高到 1024（8 token 会消耗在思考阶段），连接测试 20 秒，实际台词请求仍为 5 秒。

已保存 GLM-5.3-Flash 配置在普通 API 返回 HTTP 429、业务码 1113（官方说明为账户欠费）；同一密钥在 Coding Plan 接口实际返回有效正文（3901ms）。在加密数据库及配套密钥文件备份 data/backups/remote-endpoint-1792031674657.sqlite 后，仅将这一条配置改为 https://open.bigmodel.cn/api/coding/paas/v4，保留密钥。通过真实 18081 游戏服务按配置 ID 调用返回 HTTP 200、有正文、3154ms。日志和验证输出不包含密钥及提供商原始错误正文。

24 项相关单元/代理/数据库测试、生产构建通过。审查未发现重要问题。智谱错误码使用固定中文映射（欠费、限流、套餐到期、模型权限等），不透传上游原始错误。

运行服务更新前通过 node:sqlite backup 保存到 data/backups/remote-settings-1792030446689.sqlite，快照数量 161。只重启 18081 的本项目世界服务；健康检查 errors=0，新增 session 接口可用。回滚代码不会删除新增表；数据库备份和对应 .remote-key 文件应配套保留。
