# 社会互动审核与词库维护

## 编辑词库

编辑 `config/moderation/blocked-words.txt`，使用 UTF-8，可带 BOM。一行一个字面词语或短语；空行及以 `#` 开头的整行忽略。不是正则表达式。按 2026-10-15 用户最新要求，当前仅配置“共产党”“党员”两个词。

保存后连续两次一秒轮询读取一致内容才切换，通常约 2 秒，无需重启。支持编辑器原子替换。文件丢失、乱码、超限会保留上次有效版本；启动时没有有效词库则输出安全占位。有效空词库表示不屏蔽任何词。

匹配会规范大小写、全半角、零宽字符及空格、点、下划线、连字符等分隔符。全部重叠命中区间合并，替换为字面量 `**`。最长单条 128 字符、最多 10000 条、文件最多 512000 字节；避免把过短常用字加入规则而误伤大量文本。

## 审核和兜底

当前采用词库即时屏蔽，取消大模型语义审批。普通系统消息、历史记录和已生成文本直接显示，命中片段替换为 `**`，不再显示“内容审核中”或“内容暂不可显示”。MLP 世界 tick 不等待模型。

认知结果写入前也按词库屏蔽；结构、身份、动作权限和世界状态校验继续保留。客户端旧 `dialogue-result`、`caption` 接口不可直接发布 NPC 文本，`social-chat` 任意文本被拒绝。玩家只能提交服务端候选项 ID；更换一批只作废旧候选项，不能发送消息或建立约定，服务端限制三秒内重复刷新。

“更换一批”携带上一批选项作为生成上下文。新生成结果须结构校验和词库过滤；完全重复、无效或失败的结果降级为安全退出选项，不承诺模型每次都能提供新选项。

词库更新后旧选项无法提交，历史显示缓存失效。世界重置和模型切换会使在途结果失效。轮询稳定判断不能识别长时间停留的半文件，维护时推荐先写临时文件再原子替换。

## 运行与观察

- `GET http://127.0.0.1:18081/game-api/health`：检查 `socialProtocol: society-v1`、`moderation.ready/version/error/accepted/blocked/failed`。
- `CAMP_BLOCKED_WORDS` 可指定词库绝对路径；`CAMP_WORLD_DB` 指定数据库。
- `CAMP_SOCIAL_OFFLINE=1` 仅用于离线故障测试，让社会生成失败并走安全兜底，不能关闭审核。
- Windows 修改世界服务源码后执行 `npm stop`、`npm start`；仅刷新网页不更新后端。
- 真实模型验证：`node --import tsx scripts/validate-social-model.ts --configured`。可用 `--model=native:qwen3.5-0.8b` 单独验证已安装模型，不改变玩家设置。测试输出不含密钥或拒绝原文。

此前 MiniMind3 的语义审核失败记录属于旧策略；现在不再调用语义审核器。模型生成是否符合社会意图结构仍会单独校验。

## 备份与回滚

上线前使用 Node SQLite `backup()` 在线备份，包含 WAL 中已提交事务；不要运行时只复制主数据库。2026-10-15 的备份为 `data/backups/world-before-social-1792072702644.sqlite`，`PRAGMA integrity_check` 为 `ok`。

回滚前停止游戏服务并再备份当前数据库，再恢复与备份时对应的源码和 SQLite。保留回滚前进度备份，明确恢复旧备份会失去之后的新进度。不要直接用旧版本解析并覆盖新社会状态，也不要把旧文件连同仍运行的 WAL/SHM 混用。开发工作区有大量原有未提交变更，不能用整体 Git reset 充当回滚。
