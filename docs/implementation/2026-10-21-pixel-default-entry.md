# 默认二维入口切换与main合并

## 用户要求

合并main、不保留独立验收入口、替换默认游戏、合并后删除功能分支。

## 实际改动

默认Unity场景改为已保存的 `Assets/CampMind/PixelWorld/PixelGame.unity`。原“打开Unity编辑器.cmd”及“运行游戏.cmd”保持用户入口名称；npm start与npm run build分别继续调用同名play/build脚本，但它们不再查找或回退旧3D包。删除“打开2D像素地图.cmd”、旧open-pixel-map.ps1与独立验收菜单。

复用原编辑器启动器的IPv4/IPv6 BuildReport端口保护和进程交接处理。编辑器中已有未保存场景时仍先询问保存，不直接覆盖。新增二维IL2CPP构建方法，构建失败不更改之前的二维构建指针；编译报告、源码指纹及整包产物哈希一致才发布pixel-current.json。源码更新后旧EXE明确拒绝启动。

默认地图协议scope改为pixel-game。编辑器与EXE共用 `native/LocalData/pixel-world-v1/world.sqlite`，只绑定本地回环，保留令牌、进程互斥、事务、幂等、有限资源与所属进程关闭机制。

## 不得混淆的限制

这次完成的是**默认入口与构建链切换**，不是完整游戏玩法迁移。当前仍只有一个受控地图角色；九名NPC、MLP、正式生产链和大模型社会化不在当前地图运行链中。源码仍保留供后续接入，没有删除或伪造这些功能。

旧玩法存档和旧二维验收存档保留在原目录，当前不自动迁移人物、库存、装备、记忆或正在进行的工作；二维地图读取新的版本化数据。不能宣称“旧局已继续”或“完整游戏已升级完成”。

当前环境不能直接访问用户Windows/Unity，因此没有执行Unity编译、EditMode/PlayMode、原生截图、帧率或EXE验收。GitHub合并源码不会自动改变用户硬盘上的EXE；需要同步main后在指定Windows工程中重新构建。

## 验证

本地Node22.16.0运行 `node --test tests/pixel-world/*.test.mjs`，本轮实际结果为44/44通过、0失败、0跳过。测试覆盖原25项地图检查，新增默认入口、已保存场景GUID、旧3D回退禁止、构建失败与旧指针保持、源码变更、文件损坏/路径越界，以及真实本机宿主关闭。客户端生命周期测试使用明确的Node子进程夹具，不冒充Unity。

GitHub原有像素地图CI继续在Node24执行这些测试并检查C#9语法，实际结果以Actions为准。历史全仓库CI保持原样，不通过修改旧测试掩盖缺失的退役资源与模型。
