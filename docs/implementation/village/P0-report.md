## 测试与审查

T01／T02／T03 均保存了真实失败与通过日志。S00 是范围登记与来源核验，不人为制造功能失败。

独立审查发现并修复：结构化补充参数可为空而被视为已配置；JSON 边界缺少数值域、必需嵌套值、唯一性和引用验证；Excel 波次身份、日期和狼引用校验不足。分别先增加失败测试，再修复并验证。另将损坏 ZIP/XML 未输出失败报告的问题提升为导入契约问题，补充失败测试后修复。没有留待下一阶段的审查缺陷。

完整测试夹具独立放在 `tests/fixtures/village/`。其工时、经验、食物、负重、招募与治疗值仅用于状态机测试，不能被宣称为原表平衡或用户已批准的正式参数。`configured` 仅表示参数完整；实际动作仍须在 P1—P3 实现。

最终命令与数量另见同目录 P0-report.json；基线和现有 UI／构建限制见 baseline.md。阶段归档保存于本机 `native/Artifacts/village/P0/`，不包含玩家旧存档或推理密钥。

最终全量验证：119 文件通过、1 文件失败；760 测试通过、2 项既有寻路失败，退出码 1。新增 P0 的 28 项测试全部通过。整仓类型检查与新增模块类型检查均通过。归档包为 `native/Artifacts/village/P0/stage.zip`。

回滚只处理本批次新增的 village 模块／工具／测试／文档与源表副本；共享文件只撤销 P0 新增的三个 npm 命令、README 的 P0 段落和旧时钟相对端点这一处改动。SHA256SUMS 也收录只读共享文件用于核验，它不是删除清单；不能整文件删除 package.json、README、旧时钟或旧模型 manifest，更不能整仓 reset。

## 实施裁决与代价

1. 继续当前明确授权的 Unity 工作区，没有另建缺少在途地图和 Web 清理成果的检出；代价是共用文件必须持续核对，不能重置其他任务改动。
2. 不混合提交其他任务的脏文件；当前改动尚未形成提交，使用文件清单与哈希作为可审查边界。代价是回滚须按本批次清单处理，不能整仓 reset。
3. P0 不将 `village-v1` 标签套在旧引擎上；新模式服务接入保留给 T04／T05。代价是当前游戏仍运行旧玩法，本批次不是可玩新版本。
4. 补充参数结构使用显式工程契约，数值仍为具名试验或测试夹具。代价是 P1／P2 冻结接口时可能需要升级契约；正式规则不会自动被这些值替换。
