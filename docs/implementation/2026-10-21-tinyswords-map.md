# TinySwords 地图改造与验收

## 实现范围

以已确认的原规划布局为依据：保留32km区域、五间民居、寨主住所、工坊和仓库，重排民居与自然支路，围绕公共火塘和水井形成公共活动区。寨墙削去矩形四角，实际碰撞使用同一组墙段；村北支流移出寨墙，北桥移到村寨东北侧。村内补充花草、庭院、树木、木料堆、箱子、长凳、灯与旗帜；环境装饰不产生虚假库存。

TinySwords用于草地纹理、水岸细节、树木、灌木、岩石、金矿石、树桩、人物与火焰动画。中式木屋、议事厅、仓库、工坊、木寨门及附属设施仍使用本项目补充的像素绘图，并非把西式城堡改名成中式议事厅。山地与雪山增加山峰实体表现，湿地增加芦苇。

按用户后续截图要求，村寨周边与普通林地以Tree3、Tree4阔叶树为主，混合黄绿与金黄树冠；近郊新环境树约88%为阔叶树，普通林地约76%，山地丘陵增加针叶树。包含原有资源树在内，村寨300米内实测587棵树，其中471棵为阔叶树，约80.24%。资源树ID与碰撞半径不因树种外观调整而重置。

山地使用TinySwords图集右侧岩壁区域的纹理，限制在本项目补充的连续山体轮廓内，避免大幅矩形图集方阵；雪山保留雪顶和岩面明暗。湿地由权威地形生成实际不可通行水洼、沙岸和可通行芦苇带。区域图的树木/山地符号按真实地形取样并确定性错开，避免整齐的图标方阵。

`TinySwordsImport.Prepare`生成Resources素材引用目录、调整所用纹理为可读、Point与无压缩；精灵动画按真实帧数裁切，各帧共用包围盒。PNG原始素材保持在ThirdParty下，运行时通过显式Resources引用进入构建，不调用AssetDatabase。地表按1024像素/128米绘制，66×66地形边缘采样避免相邻区块分类接缝。

## 存档与构建

- 旧玩法存档、模型与配置不受本次地图宿主操作。
- 旧二维档首次升级到layoutRevision 2时，用SQLite VACUUM INTO创建完整备份；库存、采集剩余、操作幂等账本与探索记录保留。只有被新碰撞阻挡的原站位会在128米内寻找最近一圈安全点，失败则拒绝升级；迁移记录保存原位置、新位置及备份路径。
- 当前二维库仍位于`native/LocalData/pixel-world-v1/world.sqlite`；布局升级备份位于该库相邻的`backups`目录。
- 素材PNG、Importer元数据及Resources引用资产进入源码指纹，素材变化不能绕过旧EXE过期检测。
- 默认构建脚本先准备素材再计算源码指纹，再生成Windows IL2CPP包。游戏退出、资源采集、门开闭仍由原有宿主协议负责。

## 验证方法与边界

`node --test tests/pixel-world/*.test.mjs`覆盖布局连通性、村北河流、地形边缘、资源持久化、旧布局备份迁移、HTTP与启动链、素材变更后过期检测。

`scripts/unity/review-pixel-map.mjs`通过正式启动链启动真正的EXE，使用`-pixel-visual-probe`保存村寨全景、公共空间、村北桥与林缘截图；相机移动不传送玩家。`visual.json`记录连接、截图数量与静止场景平均帧时。静止帧时不等同跨区域流式加载帧时或整局性能验收。

九名NPC、MLP、生产与社会化尚未迁移；本次不据此声称完整玩法已接入，也不以景物、人物动画代替实际NPC行为。
