# 统一启停本地游戏

2026-10-15。默认使用 `npm start` 启动网页和世界服务，`npm stop` 同时停止；启动终端 Ctrl+C 走同一关闭流程。旧 `npm run dev` 与 `npm run world` 保留为独立调试入口，`npm run dev:local` 的默认模式转到统一入口。

## 生命周期

统一入口拥有 Vite 实例和带 IPC 的世界子进程，等待世界健康检查成功才启动网页。启动前检查两个端口，不静默复用旧后台。任一启动失败会关闭已创建的服务。退出时先关闭网页，再通过 IPC 让世界补存当前状态、关闭 SQLite 并退出；超时才终止自己拥有的子进程。父进程意外退出后，世界通过 IPC 断连事件自行保存并退出。

停止命令使用同项目 `data/local-game-default.json` 中的随机令牌连接本机控制接口，不依赖固定 PID。旧版遗留服务没有控制接口时，Windows 兼容脚本先核实监听端口、Node 进程、命令行及世界健康接口中的项目根目录，再停止本项目旧进程。任一归属不明确时不执行停止。不会清空存档或结束其他项目的 Node 进程。

## 验证

19 项相关测试通过：在独立端口和临时 SQLite 中运行真实统一入口，验证启动、单命令关闭、两个端口释放、SQLite 完整性、再次启动、父进程终止后的后台退出、失效控制记录恢复，以及占用端口时拒绝接管其他服务。旧版停止脚本使用隔离 PowerShell 的模拟进程命令测试归属验证，未停止在线服务。包含既有世界持久化和真实 HTTP 服务回归。

全项目构建首次修正本任务的测试未用导入后通过过；随后工作区新增的并行 `npc-collectives` / `collectives.ts` 改动出现缺失模块及类型错误，最终完整构建仍被该独立改动阻塞。本任务未改写这些正在变化的实现，也不将启停相关测试通过等同于全项目构建通过。

## 重复就绪检查修复

用户实机启动日志显示世界服务已监听，但 Vite 插件随后报“统一启动的世界服务未就绪”。统一启动器已经成功完成健康检查，插件又重复发起 500ms 检查，短请求失败会误判整次启动。新增超时回归先复现该失败，再让托管模式由拥有子进程的启动器负责就绪检查与退出监控；插件不重复检查或另建后台。独立开发入口保留原健康核验。

修复后 21 项插件、统一启停、旧后台归属及真实世界 HTTP / 持久化测试通过。最新构建被工作区另一项尚未完成的 `tests/npc-memory-presentation.test.ts` 引用缺失 `NpcMemoryPanel` 阻塞，启动器测试未受影响。

同时处理配置异常发生在 Vite 实例返回之前的资源残留：启动失败会先等待已有世界子进程关闭，再以失败码退出整个专用启动器，避免残留文件监听器或端口。上述 21 项测试在这项修改后重新通过。修复之前已残留的旧启动终端需先退出，再用新入口启动。
