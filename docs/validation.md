## 浏览器覆盖

1. 真正加载并运行本地 MLP；NPC 移动，暂停时安排任务，恢复后的实际模型输入含指令。分食扣库存并改变饥饿值。空格正确激活聚焦的音效按钮。导出记录包含 36 维输入、8 个动作分数、合法动作和真实来源。
2. 390 × 844 触摸视口：开场、游戏和观察窗口可用；游戏无页面溢出，五项主任务均至少 44 × 44 像素，选中头像保持 36 × 43 像素。相机展开、缩放、复位、标签拖动和暂停继续可实际点击。
3. 360 × 740 与 844 × 390：旋转同一个 3D 世界，投影同步变化，拖动不会误派移动指令；任务始终留在视口内。
4. 点击真实 3D 篝火位置：阿壮到达火边，记录 `campfire / burn` 及对应台词，健康下降，移动指令解除，位置仍在实体外；模型记录仍为真实模型来源。
5. 通过真实 `WEBGL_lose_context` 扩展中断绘制：显示恢复提示，游戏暂停，倒计时停止；点击重绘后恢复一个有效 WebGL2 画布，再继续可推进时间。
6. 生产 Service Worker 确认全部资源缓存后断网；重新加载、恢复存档、安排工作，产生比断网前更新的本地模型决策 ID。
7. 完整轻松局：按真实 tick 推进，在最后半分钟召回；验证胜利、三人存活、记录导出、重开后速度和记录初始化。
8. 严酷风雨 seed 7：无人指挥进入真实失败结算，并检查对应的模型记录。
9. 模型 manifest 返回 503：明确显示错误并阻止模型局开始；用户选择规则入口后，全部记录标为规则来源。

这里按功能分为 9 组，对应 **10 条 E2E 用例**，其中两种附加手机尺寸各有一条。最终分组验证中，前 7 条均通过，严酷风雨失败和 503 规则入口两条通过，胜利/记录/重开单独复跑通过（测试约 4.3 分钟、含启动共约 4.5 分钟）。这些是软件图形环境中的测试耗时。

### 整局测试的时间和图形范围

完整胜负流程使用 **390 × 844 手机触摸视口**，胜利连同重开流程最多 360 秒，失败流程最多 240 秒；其余用例保留 90 秒。`clock.runFor` 逐个执行计时器和每个 0.1 秒模拟步，没有跳到预设结局。WebGL 照常渲染；这项时间预算用于软件 GPU 环境中的整局检查。

桌面整局的首轮运行在 90 秒预算内未完成受控时钟推进，因此改在主要目标手机视口验证。Playwright 保留 DOM 与源码 trace、失败截图与决策面板截图，关闭持续截图 filmstrip 以减少额外读回和编码。完整局不额外截图，以免画布读回把功能验证阻塞在渲染队列上；胜负、角色状态、记录与重开仍通过真实界面及下载 JSON 断言。这个调整只影响测试记录方式，不修改游戏状态或渲染逻辑。

## 物理、输入与音频检查

物理用例覆盖跨火堆路线、连续扫掠与滑动、安全工作站位、危险对象的不同伤害、接触冷却、同伴分离及确定性回放。审查复现并修复了两个卡人案例：目标被同伴占据时可以在接触边缘完成移动；被帐篷和同伴夹住时改从另一侧绕行。新增的八棵林缘树都有真实阻挡，任务站位保持可达。

独立交互复测确认：从篝火标签开始的 12 像素拖动产生 **0 条指令**，普通点击恰好产生 **1 条**；人物透明触摸区域重叠时，可见的小米身体仍选中小米；Enter 各触发一次；一指在标签、一指在画布的双指手势不误派任务。四个视口中的四个展开相机按钮及暂停继续按钮均命中自身中心，最小尺寸 44 像素。复测没有页面脚本错误。

音频测试检查五种反应波形、三人的差异、有限幅度、静音/未解锁时不创建音频设备、源对象台词传递、语音队列取消，以及缺少本地中文语音时的降级。Web Audio 与 SpeechSynthesis 的生命周期边界使用测试替身；没有把它当作真实设备语音引擎的听测。实际设备无本地中文语音时仍有合成叫声和中文气泡。

## 环境与边界

环境为 **Node.js 24.19.0、Linux x64、Chromium 153.0.8010.0、SwiftShader WebGL2**。通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE=/tmp/chromium` 指定本环境浏览器。普通开发环境按 README 安装 Playwright Chromium 即可。

手机检查属于视口与触摸仿真，未进行真机持续帧率、发热、内存或 Safari/Firefox 验证。网格构造约 342,127 个三角形；默认画面含阴影通道约 487,028（手机）和 511,444（桌面），不是手机硬件性能承诺。游戏物理是确定性的地面碰撞和避障，不包含重力跳跃、布娃娃或可推动刚体。

GitHub Actions 已有单元测试、生产构建和 Chromium E2E 工作流；远端运行结果以仓库 Actions 页面为准。
