# 本地策略与天气游戏评估

本页记录固定 **0.1 秒模拟步长**的真实游戏回合。[评估脚本](../scripts/evaluate.ts)读取仓库内的模型 manifest 和 Float32 权重，校验 SHA-256，然后调用与游戏相同的 `inferPolicy`、`baselinePolicy`、`createGame`、`advanceGame` 和 `issueCommand`。模型推理和游戏状态均实际计算，没有网络推理或预设结局。

本次天气版本共 **14 局、1,437 次决策、0 次异常回退，只有一个种子 7**。普通难度无人指挥时，小模型成功 3/3 局，规则策略成功 2/3 局；严酷难度下两种策略均成功 0/3 局。严酷雷暴案例加入救援指挥后，两种策略维持营地的时间均延长，但最终仍因篝火熄灭而失败。这个种子是开发时选定的挑战案例，不能把这些比例当作随机抽样得到的总体胜率，也不能据此宣称模型优于规则。逐局结果和复现元数据均见 [evaluation-results.json](evaluation-results.json)。

## 运行方法

安装项目依赖后，在仓库根目录执行：

```bash
npm run evaluate
```

默认只输出 `console.table`，不写评估文件。需要完整、可自行分析的 JSON 时：

```bash
npm run evaluate -- --output ./evaluation.json
```

输出目录须已存在。同一路径的旧报告会被覆盖。可更换无人指挥矩阵的种子，或者查看帮助：

```bash
npm run evaluate -- --seeds 7,64138 --output ./evaluation-two-seeds.json
npm run evaluate -- --help
```

默认矩阵是 `1 个 seed × 3 个 scenario × 2 个 difficulty × 2 个 policy = 12 局`，再运行 2 局救援；两局救援的无人指挥对照直接复用矩阵中的回合，不重复计数。上面的双种子命令会得到 24 局矩阵加 2 局救援，共 26 局。救援案例始终使用 `hard / storm / seed 7`；如果 `--seeds` 不含 7，脚本另补这两局无人指挥对照。

入口使用 `node --import tsx scripts/evaluate.ts`，无需开发服务器或浏览器。模型缺失、格式错误、权重校验失败或评估期间所记录的源码发生变化时，脚本明确报错并返回非零退出码。

## 评估约定

| 项目 | 约定 |
| --- | --- |
| 场景 | `standard` 寻常的一天、`storm` 风雨将至、`conflict` 各有心事 |
| 难度 | `normal` 荒野求生、`hard` 严酷长夜；默认样本不包含轻松露营 |
| 模型策略 | 已训练的 **41 输入、6,445 参数 MLP**，直接加载 **25,780 字节** Float32 权重；观测契约为 v2 |
| 规则策略 | 模型训练时使用的同一套 teacher utility 函数，未经刻意弱化 |
| 时间推进 | 每次实际调用 `advanceGame(state, 0.1, policy)`；调度使用整数 tick |
| 无人指挥 | 初始状态之后不调用 `issueCommand`；`conflict` 自带的初始采木指令仍然保留，并另存为 `initialNpcCommands` |
| 天气 | 运行引擎的随机天气、阵风和雷电；本次所有回合均不主动发出天气切换命令 |
| 胜利 | 240 秒时三人存活、篝火未灭，且所有人位于引擎规定的营地安全圈内 |
| 失败原因 | 按引擎结局顺序区分死亡、灭火、天亮仍在安全圈外；同时保留原始 `resultReason` |
| 得分 | 原样记录引擎的 `score`，包含胜利加分、健康、时间和资源等；它不是模型训练损失或通用智能指标 |
| 存活比例 | 结局时存活 NPC 数 / 3；提前灭火失败也可能是 3/3，不能把它等同于守过整夜 |
| 回退 | 原样记录引擎累计 `fallbackDecisions`；不因回退而把结果写成正常模型推理 |

每局重新创建游戏状态。两种策略使用相同的种子、场景和难度。[天气模拟](../src/game/weather.ts)使用独立的无状态种子散列：角色行动不会消耗天气的随机序列，因此在相同模拟时刻、相同天气干预下，不同策略遇到相同天气阶段、阵风与雷电。两种策略仍会作出不同动作，继而进入不同的资源、身体和任务状态。天气确定性与暂停行为另见[天气模拟测试](../tests/weather.test.ts)。

精确重现要求模型文件、游戏源码、种子、命令顺序、**命令发生的模拟时刻**以及模拟步长都一致。通过界面主动切换天气也会推进天气阶段，必须保留切换值和时间；只有相同种子不足以复现有不同干预的回合。界面的 1×、2×、4× 应通过重复相同的 0.1 秒 tick 加速；将 `dt` 改成 0.25 或 0.4 会改变任务完成与事件采样时刻，不能混用结果。

### 救援指挥规则

在模拟时间 0、10、20……230 秒，且游戏尚未结束时，按以下顺序检查并调用真实命令 API：

1. 木材少于 9、时间小于 205 秒，且阿壮当前不在采木时，指派阿壮采木。
2. 篝火低于 43、库存有木材，且老周当前不在添柴时，指派老周添柴。
3. 按 NPC 原有顺序检查；饥饿高于 82 且库存有食物时，给该 NPC 分配一份食物。
4. 在 210 秒时，发出一次全队召回。

这里的两个比较分别是：在固定策略、固定初始状态下，将“无人指挥”替换为上述自适应指挥规则。因此可以查看这项干预如何改变**这一固定案例**的结局。两种策略进入的状态不同，同一套自适应规则会发出不同的实际命令序列，不能声称它们收到了完全相同的命令输入。本次两局救援都在 210 秒前失败，因此没有实际执行预定的全队召回。

JSON 的 `commands` 逐条保存 `tick`、模拟时间、完整 `GameCommand`、`applied` 和游戏反馈。`commandCount` 是实际发出的 API 调用数，包含被游戏拒绝或延迟的调用；`appliedCommandCount` 计入已登记的任务指派、召回和实际消耗食物的分食。**指派已登记不代表 NPC 一定服从**，后续动作仍由策略选择。

## 天气是否真的影响模型选择

整局成败会混合寻路、资源、人格、命令与天气的影响。为单独检查天气输入，[天气策略测试](../tests/weather-policy.test.ts)直接加载同一份二进制权重，在固定观察值与**相同合法动作列表**下比较模型输出。下表是测试中的受控状态对照，不计入上述 14 局，也不是游戏总体胜率。

| 对照 | 保持相同的条件 | 被改变的输入与实际选择 |
| --- | --- | --- |
| 晴天 → 强雷暴 | 同一谨慎、暴露在外的角色；资源、身体状态、任务许可和其他特征相同 | 只提高雨量、风力和雷暴风险，MLP 从 `food` 采食转为 `rest` 遮蔽休息；teacher 也作出同样变化 |
| 谨慎 → 勇敢 | 同一雷暴、低火势、资源与位置状态；合法动作相同 | 只提高勇敢程度，MLP 从 `rest` 转为 `fire` 添柴；teacher 同样在两个动作间切换 |
| 分别增加雨量、风力、雷暴风险 | 其余所有输入及合法动作相同 | 三个输入分别变化时，真实权重计算出的动作 logits 都有变化；不要求每一次都改变最高分动作 |

同一测试文件还检查湿透角色选择休息、火势紧急的勇敢角色选择添柴，以及连续天气强度下输出有限且合法。天气本身不会通过删除采集动作强迫角色躲雨。引擎遇到天气或雷声时请求新的策略决策，再执行其实际选择；当前任务被再次选中时保留进度，手动移动和携带物资返程受到保护。相关执行行为见[引擎天气测试](../tests/weather.test.ts)。

这些案例说明交付的 MLP 会读取天气和遮蔽输入，并在具体状态下改变分数或行动。其偏好来自人工设计的教师效用函数与合成训练数据，未通过在线游戏自行学得。模型卡中的留出一致率衡量模仿教师的程度；它与这里的整局成败是不同指标，训练方法及限制见[模型卡](model-card.md)。

## 输出字段与复现边界

`--output` 导出的报告使用 `schemaVersion: 1`；其中模型的 `observationSchemaVersion: 2` 表示天气输入契约，模型二进制格式仍为 `version: 1`。

| 字段 | 内容 |
| --- | --- |
| `environment` | Node.js 版本、系统、CPU、评估实际耗时及计时范围 |
| `protocol` | 固定步长、矩阵种子、场景/难度/策略、救援阈值与命令顺序 |
| `model` | 模型元数据、权重 SHA-256、manifest SHA-256 |
| `sourceSha256` | 引擎、常量、类型、观察值、地形、物理、**天气模拟 `src/game/weather.ts`**、推理、teacher 和评估脚本的 SHA-256 |
| `sampleCount` / `runs` | 实际执行的回合数量及逐局原始结果 |
| `runs[].npcHealth` | 各 NPC 的健康、饥饿、体力、士气、受伤/存活状态、位置和是否在营地 |
| `runs[].commands` | 实际发出命令的时间、有序参数、是否生效和反馈 |
| `summary` | 按难度、策略、控制方式分组的样本数、胜场、灭火数、得分、存活和决策统计 |
| `rescueComparisons` | 各策略的固定种子无人/救援对照，引用回合 ID，不重复算样本 |
