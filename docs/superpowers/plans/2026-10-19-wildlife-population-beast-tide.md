# 动物繁殖、人兽冲突与生态兽潮 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 默认在当前会话顺序执行；不得自行创建用户侧新任务。

**Goal:** 让森林动物持续繁殖，生态压力积累后由真实动物形成兽潮袭寨，NPC 能发现、协作防御并恢复生产，最终在正式 Unity 游戏中可见、可玩、可验证。

**Architecture:** TypeScript/SQLite 管理确定性的种群、兽潮阶段和战斗结算；动物 MLP 控制个体生存和战斗，人类生活/战术 MLP 处理生产与防守，大模型处理基于真实见闻的预警和协作意图。Unity 读取同一权威世界，复用现有动物资源、布局和频道。兽潮与旧定时野狼波次必须统一调度，不能同时重复产生袭击。

**Tech Stack:** Unity C#、TypeScript、SQLite、Vitest、NumPy FP32 Adam、现有原生大模型宿主。

## 首轮规则合同

### 种群

- 增加年龄/成熟状态、繁殖冷却、亲本信息和稳定实例ID；可用符合条件的同种成年配对，先不扩展性别遗传系统。
- 双亲存活、健康、饱食、体力足够、同区域且有生态容量时产生幼体；出生消耗亲本资源并进入冷却。幼体不可立即再繁殖。
- 建议食草/小型动物按1—2游戏日繁殖，大型危险动物按3—5游戏日；成熟、窝数和物种上限分别配置。
- 建议软容量为初始种群的约3倍、硬上限约5倍；硬上限是性能保护，不用瞬间删除活体。压力达到阈值前停止部分繁殖，不能因容量门限让兽潮永远无法触发。
- 饥饿、捕食、猎捕、死亡正常作用于数量。长期模拟应有恢复能力而不是必然灭绝或无限增长。

### 冲突与兽潮

- 日常冲突包含主动狩猎、受击反击、危险动物饥饿捕猎人类及领地防御。兔、野鸡以逃避为主；鹿以逃跑和自卫为主；危险动物才承担主动袭寨。
- 以区域活体密度、危险成年动物数量、食物不足比例计算压力；建议密度超过软容量80%、危险成年动物至少6只并持续半个游戏日，进入聚集。物种配置决定谁有袭寨资格，不把所有食草动物变成敌军。
- 所有阶段使用活体ID：平静 → 压力积累 → 聚集 → 接近 → 进攻 → 撤退 → 冷却。各阶段设置超时与失败退出，避免永久卡住。
- 预警只在侦察、视野或声响事件被角色实际感知后产生；系统可显示生态趋势，但NPC不能凭空知道全图兽群。
- 首轮每波建议参与8—16只，不能超过现存合格动物；严重伤亡、低体力、进攻超时或目标失效触发撤退；冷却建议2游戏日。
- 袭击现存寨门/围栏和暴露人员，禁止穿墙、瞬移和寨内刷新。封闭且不可达时选择可攻击的边界或退出，不能原地循环走路。
- 不把MLP设为繁殖、触发波次和资源结算的裁判；这些都由规则决定。

## 跨系统数据合同

- 种群存档包含 `schemaVersion`、`nextAnimalId`、出生/死亡累计计数、每只动物成熟时间/亲本/繁殖冷却；迁移以确定性默认值补齐，出生和事件序列不得复用ID。尸体耗尽并超过保留期后清理实体，保留汇总与必要历史，避免长周期死亡列表无限增长。
- 兽潮包含 `id`、`phase`、`memberIds`、`phaseStartedAt`、`cooldownUntil`、`seed`；存档中的同一动物只有一个权威对象，兽潮仅引用ID。
- 目标使用显式判别类型 `animal | human | gate | fence`；攻击执行器分别验证存活、敌对关系、距离、视线、门墙段和冷却，动物不能通过扩大允许列表绕过原有人类/建筑权限。
- 攻击动物和狩猎如果新增候选动作，必须同步动作合同、观察维度、特征hash、采样器与全部受影响模型；不把新动作塞进旧输出后声称旧权重已学会。兽潮规则决定阶段和目的地，MLP在阶段约束下选择合法个体动作。
- 调度只推进一次固定100ms生态步；离线追赶不能重复繁殖或重复扣门墙血。所有压力、日龄和冷却统一使用权威游戏时间。

## 最终验收标准

1. 不重置原存档也能兼容升级；动物在合适条件下真实出生、成长、死亡并持久化。
2. 捕猎确实降低压力；高压持续积累能触发兽潮，低压不会靠定时刷怪假装触发。
3. 参与兽潮的动物在森林、集结、进攻和撤离阶段始终是同一批实体。
4. 兽潮能通过真实路径攻击现有门墙/人物；NPC能识别、反击、撤离、救援，之后恢复工作。

## 用户补充：触发频率与全屏预警（2026-10-19）

- 当前正式规则一天=白天480秒+夜晚240秒，即720游戏秒；正常1倍速约12分钟，2倍速约6分钟，4倍速约3分钟，不计暂停及运行积压。
- 兽潮不是固定间隔事件。持续高压半天=360游戏秒；前一波结束后冷却2天=1440游戏秒（1倍速24分钟），冷却结束还需重新满足压力、成员和聚集条件。首次发生时间不能由现有参数直接给出，须由P7长周期模拟确定；不承诺每隔24分钟必来。
- 全屏预警为正式验收必需项：全屏半透明危险暗角/色罩、中央“兽潮来袭”大字及来袭方向、警报音/号角。首轮强提醒持续3—5个真实秒，随后收为常驻危险条，不能遮黑场景、吞掉操作或要求玩家点击确认；尊重音量和减少动态效果设置，避免频闪。
- 阶段分级：实际发现兽群聚集时给“兽群聚集，准备防御”；接近村寨时升级为“兽潮来袭”；门墙破坏时给“寨门失守”等紧急提示；撤退时给结束提示。世界频道保留同一事件历史。
- 正常提前发现的首波通过聚集阶段争取至少120游戏秒准备窗口；近城才发现时立即紧急警报，不凭空回退动物或伪造提前预警。界面优先显示方向和实际阶段；没有可信预计到达时间就不展示精确倒计时。
