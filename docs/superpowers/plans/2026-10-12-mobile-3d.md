# CampMind Mobile 3D Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or native execution with independently scoped review. All implementation happens on feat/mobile-3d-camp.

**Goal:** A mobile-first full-screen Three.js camp with obstacle-aware NPC movement, contact damage, expressive reactions, and preserved local-policy gameplay.

**Architecture:** Keep the pure deterministic game engine. Share one terrain geometry definition between navigation, collision and the Three.js renderer; HUD and audio consume game state/events.

**Tech Stack:** Existing React 19 / TypeScript / Vite, Three.js 0.186.1, deterministic TypeScript navigation/kinematic collision, Web Audio and browser speech synthesis.

**Spec:** docs/design/mobile-3d.md

## Global Constraints

- Preserve current forest green/amber art direction and character identity.
- Main play surface is 100dvh with touch-safe HUD; support portrait, landscape and desktop.
- Do not change the model's 36-dimensional feature order or claim LLM dialogue.
- Preserve synchronous advanceGame and v1 old-save compatibility.
- Share ground geometry; renderer never determines damage or authoritative positions.
- Work on separate file scopes; each task reports behavior, commands and unresolved risks. Root integrates and reviews before commit.

## Review Focus

- A route crossing a fire or obstacle must remain outside the collider at all substeps, including high speed and initial overlap.
- Damage reactions must not overwrite or flood each other and must stop in pause/mute/background.
- Resumed saves must retain collision cooldowns and reject malformed optional fields.
- Mobile short screens and landscape must retain reachable primary controls without page scrolling.
- WebGL initialization/context loss, offline reload and renderer disposal must not break the game or leak animation loops.
