# 游戏级对话模型设置

用户已批准统一模型管理设计及Web开发/桌面宿主边界，要求执行。默认MiniMind3；可立即切换原生Qwen3.5-0.8B及已有2B、4B，显示真实加载进度，设置跨刷新/新局持久化，不重开游戏。

浏览器侧ModelManager通过Runtime接口选择MiniMind WASM或Native HTTP适配器；未来桌面宿主实现相同接口，无需重写游戏设置与对话逻辑。Vite插件在开发和preview时安装同源桥接，按需启动项目内llama-server router，限制一个原生模型，读取/models/sse中的真实loading progress（load-mode none）。桥接只允许项目清单中登记的模型，不接收任意URL或shell参数。

游戏设置与人物初始设置分开。选择立即取消旧生成/旧加载代际、清空调度缓存、卸载旧运行后端并启动新模型；迟到回复不得提交。加载失败保留所选模型与错误，游戏用即时回应，不静默切换。MiniMind默认启动保留现有延迟到场景就绪策略；用户手动切换无需等场景或开局。

设置面板显示选中模型、运行后端、阶段、真实百分比/不定进度、耗时、错误与重试。纯静态部署保留MiniMind；原生模式明确提示需要本地宿主，不能宣称静态网页可启动exe。桌面exe打包不在本次范围。

原生模型注册配置gamesoul/models.json：稳定ID、名称、项目内相对GGUF路径、SHA256、上下文和CPU线程。后续其他兼容GGUF登记后自动进入界面，不硬编码UI。对话只生成短中文台词；既有动作策略/存档保持原职责。原生来源以实际模型ID记录并保持旧MiniMind来源兼容。

验收：管理器默认/持久化/快速切换/迟到结果；桥接路径、Origin及模型校验；真实原生加载进度和中文推理；游戏UI切换/错误/刷新；npm test、npm run check:npc、npm run build。测试替身必须明确与真实模型证据分开。
