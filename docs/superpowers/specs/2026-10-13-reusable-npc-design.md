# 可复用 NPC 系统与营地人物升级设计

日期：2026-10-13。基线：`d91405f`。状态：本设计先于产品代码变更完成，现已按配套计划实施并验证。

## 1. 目标与玩法变化

NPC 应当根据性格、当前身体状态、亲历事件、信任与记忆作决定。性格不是固定台词表，也不把 MBTI 类型当成善恶或行为的硬性开关。人物可以忍耐、谈条件、偷懒、拒绝命令、擅自休息，或在有共同不满时联合停工。语言必须表达已经形成的立场，不能每次重新变回礼貌的初始状态。

老周改为精于算计的老油条：低勤奋、低诚实、自利、擅长掩饰，倾向接轻活、磨洋工、推责和机会主义。林枫改为懒惰、偏激、冲动、自尊敏感：即使身体还能工作也可能逃避；被连续催促或拒绝后会直接顶撞、停工、拉拢伙伴。显示名改为林枫，内部 ID `linlan` 保留，以兼容既有存档、关系和模型。其他三人的优点和缺点继续保留。

本次“造反”落实为可执行的集体拒工与挑战玩家分工：参与者各自决定是否加入、是否退出，不把一次抱怨直接升级为全体敌对。不新增战斗或领地系统。

## 2. 目录与依赖边界

## 3. 通用核心数据与接口契约

所有强度统一为 `0..1`，时间统一为宿主传入的模拟秒。核心不读取系统时钟、不用全局随机数、不创建定时器、不改变世界资源。宿主拥有 MindState；调用方已经持有可修改的模拟副本，核心函数只修改传入的心智状态，并返回需要宿主执行的结果。状态全部可 JSON 序列化。

`PersonalityTraits` 包含 `diligence`（勤奋）、`empathy`（共情）、`honesty`（诚实）、`selfInterest`（自利）、`impulsivity`（冲动）、`autonomy`（自主）、`patience`（耐心）、`fairness`（公平敏感）、`courage`（胆量）。这些是游戏参数，不是医学或心理诊断。配置稳定，情绪、诉求、信任和意图随经历改变。

核心公开以下职责明确的接口，字段细节以带中文注释的 `types.ts` 为准：

```ts
createMind(profile: NpcProfile, now?: number, seed?: number): MindState
receiveEvent(mind: MindState, profile: NpcProfile, event: MindEvent): AppraisalDelta
updateMind(mind: MindState, profile: NpcProfile, observation: MindObservation): void
decideBehavior(mind: MindState, profile: NpcProfile,
  observation: MindObservation, offers: readonly ActionOffer[]): BehaviorDecision
isValidMindState(value: unknown): value is MindState
```

- `MindObservation`：模拟时间、疲劳/饥饿/疼痛/暴露程度、工作负担、不公平程度、对当前指挥者的信任、命令动作 ID、实际可知的同伴抗议信息。信任的权威值由宿主保管，核心事件返回一次性的信任变化；不另外保存一套相互覆盖的玩家信任。
- `ActionOffer`：宿主提供不透明 `id`，通用语义 `kind` 为 work/rest/eat/shelter/aid/idle/explore，并提供付出、风险、自身收益、集体收益、基础策略偏好。所有候选必须已经通过世界合法性检查。
- `MindEvent`：递增 `sequence`、模拟时间、类型、参与者、诉求类别、事实摘要。拒绝、兑现/失约、表扬、催促、揭穿等作为事件输入。每个心智保存独立最高事件序号，清理旧记忆也不会重新计入旧事件；宿主保证事件按序投递。
- `AppraisalDelta`：是否处理、信任与士气变化。重复事件返回零变化，避免一次拒绝被每帧累计。
- `MindState`：版本号、语义修订号、事件游标、情绪（愤怒/怨恨/压力）、有界记忆、有界持续诉求、当前意图与表达计划。
- `BehaviorDecision`：选中的宿主动作 ID、意图、理由和投入程度；世界是否执行成功，由宿主重新核验。核心绝不直接增加物资、瞬移或完成工作。

意图至少覆盖 cooperate/endure/bargain/evade/rest/refuse/recruit/strike。表达至少覆盖说明、请求、谈条件、抱怨、拒绝、掩饰、拉拢。意图有开始时间和最短维持时间，避免一帧停工、下一帧又被旧策略叫去工作。

## 4. 持续诉求与实际行为

休息诉求拥有独立生命周期。同一次疲劳未缓解前，拒绝次数与阶段保留；只有实际休息使疲劳回落到恢复阈值，才关闭诉求。再次劳累才建立下一轮。提示发出标记与冷却独立，不能靠延迟几十秒重置人格。

典型流程：劳累产生诉求 → 发出请求 → 玩家拒绝产生一次事件 → 性格决定继续忍耐、谈条件或自主行动 → 动作执行产生真实恢复或后果 → 诉求解决。旧承诺只有实际完成休息/吃饭才算兑现。口头道歉可缓和愤怒，但不能自动清除怨恨或兑现承诺。

老周的掩饰与林枫的直接对抗通过通用 traits 产生倾向，营地适配负责中文措辞。核心不出现人物名字分支。偷懒会降低有效工作投入或选择休息，不能只换一句台词。集体停工通过实际知情同伴独立评估加入；亲近、共同负担和不满影响响应，没有共同动机的人可以拒绝。

命令、拖动、社交按钮和明确的文字安排都通过同一个合作判断，不能换个入口绕过拒绝。身体濒危、必须交回已携带物资的路程由营地执行层保护，既不能靠气话消灭背包，也不能让不满导致人物站在危险中无限僵持。

实施时补充两项营地规则：末段最后 30 秒，在明确召回或基础生存策略选择返营时，允许先进入安全集合区，原有停工立场、诉求和怨恨保持；搬运与身体紧急需要仍优先。工作收益由真实库存、火势和个人需要计算，不能因为“懒惰”配置就使人物在所有环境里永远休息。

道歉采用独立于可裁剪记忆的和解阶段：有新的负面经历，才允许一次有效道歉缓和怒气和少量恢复信任。重复说、换对话线程、暂停或读档均不会重领奖励；无冲突时说“对不起”不产生信任收益。自主同伴互助改善同伴关系，不直接奖励对玩家的信任。

## 5. 事实、内心与说辞分开

对话输入分为客观事实、私人意图、公开表达。老周可以有意说“我在检查工具”，同时实际选择歇着；这是角色的掩饰，不是世界事实。只有表达计划明确允许的掩饰才能通过校验。模型不能凭一句“交了木材”增加物资，也不能凭一句道歉重置状态。

基础台词和模型台词使用同一表达计划。模型不可用时，人物仍然有差异，仍能拒绝、抱怨或发火。取消统一的礼貌前缀。加入近期对话与持续诉求，避免忽略玩家前几次回复。异步票据包含意图/表达修订、对话行、世界会话代际；过期回复不能覆盖后来已经发生的翻脸或停工。

文字输入先支持清晰、可解释的营地意图（允许休息、拒绝休息/继续工作、道歉等），歧义句只继续对话，不假装理解并偷偷执行。按钮显示真实可选的处理方式，包括明确拒绝和核查说辞。通用包不包含中文正则或营地词典。

## 6. 旧 MLP、存档与数值兼容

原模型仍接受 41 个特征、输出 8 个动作和 5 种情绪；不改权重契约。MLP 给出基础任务偏好，上层心智做动机和合作裁决，再映射到原动作。覆盖模型选择时，决策日志应标记为规则裁决，并写明原因，不能算成模型自主输出。旧五种 emotion 是渲染投影，不再反过来每次推理清洗怨恨。

`Npc.mind` 添加独立版本的心智状态。外层存档继续使用现有 v1 信封，明确识别“无 mind 的旧存档”并迁移；新存档严格校验 mind 的范围、数组上限与序号。旧三人和旧五人存档都加载新静态配置，保留身体、已完成任务、资源与历史。迁移只建立当下初始心智，不捏造过去的拒绝事件。保留 `linlan` 内部 ID，显示名改为林枫。

## 7. 验收标准

1. 高疲劳连续被拒，不再反复回到同一句初始请求；不同性格出现不同持续行为。
2. 林枫体力充足时也可能逃避高付出任务；老周的掩饰伴随实际低投入或休息。
3. 拒绝、兑现、失约、帮助等事件确实改变后续合作；重复事件不重复处罚。
4. 同伴依据知情与自身动机参与停工，实际任务变化可从日志与界面核查。
5. 文本/按钮/拖动无法互相绕过合作判断，资源、完成任务只由执行层修改。
6. 保存恢复保留怨恨、诉求阶段和意图；旧存档更新人物显示与配置。
7. 纯包独立编译；餐厅示例使用同一核心，完全不导入营地代码；确定性回放可重现。
8. 现有天气、碰撞、搬运、末段返营、模型与紧凑 HUD 的有效约束继续通过测试。
