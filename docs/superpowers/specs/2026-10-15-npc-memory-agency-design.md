# NPC 持续记忆与社会自主行为

日期：2026-10-15

状态：范围已确认，详细规格待用户审阅。

## 目标与范围

每个 NPC 都能记住自己的行为、情绪表达、与玩家以及其他 NPC 的交流；根据经历、性格、身体属性形成持续的情绪和动机，并真正影响行为。MLP 保留日常行动能力，大模型异步理解处境和提出意图，世界服务拥有最终执行权。

用户已选择首版做到组织罢工、集体交涉、拒绝服从。武力造反、攻击、夺权和阵营战争不在首版范围。首版覆盖正负两类社会反馈，帮助、兑现和真实待遇改善必须与拒绝、失约一样产生持续影响。

## 当前代码边界

- `packages/npc-core/src/types.ts` 已有九维性格、愤怒/怨恨/压力、诉求、意图、表达计划和事件记忆。
- `packages/npc-core/src/runtime.ts` 当前最多保留 32 条心智记忆；拒工、拉拢、集体停工主要依靠阈值，随机数仅对普通动作评分做轻微扰动。
- `src/games/camp/npc/bridge.ts` 将心智意图映射到八类日常动作，并有身体保护、携带物资返送和生存库存覆盖。
- `src/games/camp/dialogue/context.ts` 选取少量近期记忆；`language.ts` 的 560 字符字幕提示词不能承担长期认知。
- `dialogue/commit.ts` 当前主要替换字幕和绑定对话行。认知提议需要独立协议，不能借字幕提交修改行为。
- `scripts/world/runtime.ts` 与 `store.ts` 是持久世界权威，SQLite 快照当前保留最近 20 份正常记录。完整经历不能无限塞进快照。

以上为本次静态代码核对，不代表新增能力已实现或运行验收。

## 总体方案

采用混合控制。记忆提供证据，大模型形成可检查的理解，高层意图策略分配候选概率，持久随机状态采样；基础 MLP 提供日常动作偏好；世界引擎校验地点、对象、身体条件和物资并执行。

扩展现有八动作 MLP 为单一全能网络会同时引入输入、输出和训练迁移；让大模型逐步接管动作会引入高延迟和重放困难。因此首版保留基础 MLP，增加独立的高层策略接口。

首版高层策略使用可解释评分和概率采样，明确标识 `utility` 来源，不宣称已经训练新的神经网络。记录特征、合法候选、概率、采样和结果，为后续训练高层网络留下版本化接口。新网络训练和效果验证另行实施；之后可替换高层评分器而不改变记忆与执行契约。

## 一、每个 NPC 的记忆

### 三种数据职责

1. 经历日志：SQLite 保存有意义的原始经历，包括动作开始/完成/失败、恢复、受伤、帮助、诉求、实际传达的发言、承诺及兑现。连续行走和每帧属性变化不逐帧记录；持续劳动按动作结果及阶段变化记录。
2. 工作记忆：快照保存有限的近期重要经历、有效诉求和关系认知，支持每次模拟决策，不依赖逐帧查询数据库。
3. 长期摘要：按主题和对象压缩旧经历，保留证据 ID、覆盖区间、版本以及仍未解决事项。近期裁剪不能清除未兑现承诺、连续拒绝计数和关键帮助记录。

经历字段至少包含世界代次、NPC、单调序号、模拟时间、事件类别、参与者、地点、来源、客观内容、主观评价、重要度和关联事件 ID。原始事件不可被摘要覆盖。

### 事实与认识分开

- “甲说领主偏心”是交流事实，“领主偏心”是甲的判断。
- 自言自语记录为自我表达，不能自动生成新的受害事件、拒绝次数或承诺。
- 未执行的计划记录为意图；只有执行完成事件能成为完成事实。
- 发言者与实际听见者分别获得自己的经历；未参与、未听见的人不自动获得记忆。
- 模型润色同一发言时更新其最终文本和来源，不重复新增交流和情绪奖励；既有模板已经传达的语义保持为同一事件。

### 检索与增长

检索先按 NPC 可知范围筛选，再按相关主题、人物、重要度、时间以及未解决状态排序。上下文必须包含当前属性、最相关未解决诉求和关键证据；超预算优先裁剪重复闲聊。

原始日志首版持续保存，不承诺无限容量。按世界/NPC/序号索引，分页读取；摘要分批生成，每次使用明确的日志水位。工作记忆、提示词和快照保持上限，并增加日志条数及数据库大小诊断。后续归档可独立实施，首版不静默删除历史。

## 二、大模型认知与表达

### 触发与输入

诉求被拒绝、承诺状态变化、重要交流、显著身体状态变化、集体事件变化时触发；普通重复劳动合并触发。每 NPC 同时最多一个认知请求，同一冲突阶段去重，全局限并发，使用模拟时间冷却。模拟主循环不等待模型。

输入包含性格、当前饥饿/精力/健康、工作负担、实际可知的分工情况、检索记忆、关系和合法意图集合。当前桥接层用所有人的负担计算不公平程度，实施时需改为本人可知的工作安排和目击记录，避免全知信息泄漏。

输出采用版本化结构：状态总结、证据 ID、情绪评价、目标、候选意图及有界偏好、可交流对象、表达计划。情绪评价通过宿主有界融合，不能直接覆盖饥饿、健康、诉求计数和权威事实；相同证据不能重复造成情绪增量。怒气、怨恨、压力继续是数值权威，丰富感受以带证据的语义描述表达，避免另建互相冲突的情绪数值。

### 能力与降级

认知任务与短字幕任务分开。沿用现有模型配置与密钥存储，通过可选结构化认知能力适配器调用；不能默认当前所有提供商或 MiniMind3 都能可靠输出认知结构。通过协议和实际返回校验后才能标记认知成功；模型标识和来源应可检查。

未配置、能力不足、超时、非法结构、无效证据或输出越界时，保留确定性心智评估和已有表达。短字幕仍可使用原有模型降级链。不能把字幕成功当成认知成功，也不要求为了本功能新增供应商或提交密钥。

### 服务端提交

认知调度放在世界服务一侧，使用现有模型桥的服务端适配边界；浏览器关闭后，世界运行仍可使用可用的服务端认知后端。仅在浏览器可用的 WASM/本机通道不作为后台认知的必要依赖，关闭页面时退回心智策略。

每份请求绑定玩家世界、世界代次、NPC、请求 ID、相关记忆水位、诉求/意图修订、身体状态区间和模拟有效期。结果进入服务端命令队列，在模拟边界重新校验后接纳；不按整个世界每帧变化的修订号一律拒绝。相关诉求变化、证据回滚、身体区间明显变化、NPC 死亡或世界重置使结果失效。

记录实际接纳的模型结果、接纳模拟时间及版本。重放使用已接纳结果，不重新请求大模型；同种子、同输入事件和同接纳结果序列必须产生同样决策。全新模型运行不保证产生相同叙事。

## 三、意图与执行

### 高层意图

复用合作、忍耐、协商、回避、自主休息、拒工、拉拢、罢工。追加明确的交流目标和对象，区分本人停工与加入某个集体诉求。候选概率由性格、身体需要、证据支持的情绪、关系、已有承诺及模型偏好共同决定；非法意图先移除，再归一化和采样。

使用每 NPC 持久随机状态，记录候选及最终理由。设最短维持时间、冷却和重新评估条件，避免每帧改变立场。不同性格影响选择概率、等待时间、招募对象和表达方式，不能仅替换台词。

### 执行映射

- 拒工和罢工停止参与被争议的工作，保持自主吃饭、休息、避险和选择性帮助能力。
- 拉拢选择本人认识且可接近的 NPC，利用现有导航发起面对面交流；不可达时等待、取消或换对象，不能远程直接改对方状态。
- 集体交涉通过社会线程呈现共同诉求、发言人、支持者及玩家回应；使用已有玩家对话和回应入口，不引入武力系统。
- 生存库存不足不能强制让罢工者替领主生产。危急状态允许自救，但不能清除不满和集体立场。
- 已经携带物资的处理复用当前返送流程，属于完成物理搬运，不代表恢复后续工作或接受领主安排。
- 真正恢复、兑现安排和谈判结果才改变诉求状态；一句道歉不能清空累计怨恨。

## 四、群体连锁

集体事件包含事件 ID、诉求来源、发起人、知情者、受邀者、明确参与者、拒绝者、阶段和相关承诺。参与者必须通过独立决策加入；看见他人停工不等于自动同意其全部理由。

阶段为酝酿、招募、交涉、停工、缓解、结束。首次发起可直接交涉或独自停工，不要求所有事件走同一条阶段链。未形成同伴支持也能维持个人拒工。

邀请产生一次真实交流，受邀者依据自己的经历、关系和性格选择支持、旁观、拒绝或劝解。使用事件/邀请 ID 防止同一轮不断邀请与重复情绪奖励；设置传播次数、交流冷却及同时活跃事件上限，允许新事实触发下一轮。双方不同诉求可关联，但不得无条件合并成全村冲突。

玩家回应应能改变过程：兑现休息、调整任务、提供食物、听取诉求、拒绝或继续催促。正向效果需以实际行动验证，谈妥但未落实的事项继续作为未兑现承诺。

## 五、持久化、恢复和重置

SQLite 增加 NPC 经历、摘要、认知结果和集体事件相关存储，以玩家世界和世界代次隔离。快照只携带有界工作集、日志水位、当前意图、群体事件投影和随机状态。

经历追加、认知接纳和对应快照推进在同一个数据库事务提交，使用稳定事件 ID 防止失败重试重复记账。旧快照恢复按该快照日志水位读取；更晚分支不得泄漏到恢复后的 NPC 认识中，恢复后生成新的分支标识并保留旧分支供诊断。

迁移前备份，兼容旧存档默认补齐新结构，只导入仍存在且可核实的历史，不编造已经裁剪的经历。版本不支持时保留数据库并明确报错。回滚运行模式可关闭认知和新社会意图、保留数据库；降级到旧程序必须恢复迁移前备份，不能声称旧程序可以直接读新存档。

重置事务清除该玩家旧世界的经历、摘要、认知结果、群体事件、快照及运行操作记录，更新世界代次并使所有在途请求失效；保留已确认的模型偏好和 NPC 初始设置。

## 六、呈现与实现边界

扩展现有桌面 NPC 资料和社会面板，展示当前状态、主要诉求、相关记忆、当前意图及集体事件进展。自言自语、玩家交流、NPC 交流使用明确渠道，世界频道只显示已实际传达的公开内容。私人动机和主观认识不得直接冒充公共事实。

通用记忆/意图契约放在 NPC 包；营地动作、地图、玩家关系和生存例外留在营地适配层；SQLite、模型调度、事务和身份隔离留在世界服务。保留原有模型配置入口和短字幕管线，避免一个大文件承担所有职责。

## 七、实施切片与验收

实现计划按以下依赖切片推进，每片可关闭开关验收：

实现计划需明确分支可见性查询、情绪融合与模型偏好上下界、冷却及意图维持时间的初始参数和版本；列出可验证承诺的完成条件、群体阶段转换和退出条件。关闭社会自主功能时保留事实与诉求，停止招募及群体调度，撤销对应执行覆盖；重新开启时基于当前状态评估，不能重放旧邀请或重复记账。关闭认知功能仅停止新请求并使在途结果失效，不撤销已经真实形成的社会事件。

1. 记忆事件与 SQLite 持久化、检索、迁移、恢复、重置。
2. 结构化认知适配与服务端调度、证据校验、状态理解和表达。
3. 高层概率意图、执行映射、面对面招募和集体交涉闭环。
4. 桌面呈现、端到端验证和性格差异情境评估。

必须覆盖：

- 行为、自言自语、双方和多方对话按各自知情范围记忆；润色、重试不重复记账。
- 摘要和近期裁剪后仍保留关键拒绝、帮助、未兑现承诺和来源。
- 相同处境下不同性格有不同概率分布；用固定种子集合验证分布和趋势，不要求每个种子都发生罢工。
- 疲劳与多次拒绝能走到协商、个人停工或招募；无共同经历的人可拒绝加入；改善待遇能缓解冲突。
- 罢工确实停止争议工作，自救与返送物资不会消除其立场；导航和封闭寨门仍有效。
- 模型超时、断开、能力不足、恶意玩家文本、虚构证据和过期返回不破坏世界、不改变客观资源。
- 关闭浏览器和服务重启后恢复记忆、关系、群体事件及随机状态；快照回退不读取未来经历。
- 重置后旧请求无法写回新世界；多玩家数据隔离。
- 使用真实可用认知后端验证“经历检索→模型理解→结果接纳→概率选择→实际行为→新记忆”完整链路；仅模拟后端测试时明确真实模型未验证。
- 桌面浏览器验证三类交流、记忆查看、玩家处理集体诉求及行为表现。构建、相关测试和 NPC 包边界检查分别报告；完整测试的既有失败不能归为本功能已通过。

性能验收检查模拟不等待模型、调度限流、数据库分页和快照大小上限。先记录当前 NPC 数量下的基线，再比较新增功能耗时与数据库增长；具体预算在实现计划中依据基线确定，不能以无测量的流畅承诺代替验证。
