# 可复用 NPC 初始值设置设计

## 目标与生效规则
用户可以逐角色修改九项性格、健康/体力/饥饿/士气/信任/恐惧初值和工作技能，保存后用于下一次新开局（包括重开）。继续旧存档只使用存档里的本局快照，不读取最新模板来重置角色。恢复默认只修改编辑草稿，点击保存才持久化。

## 分层
- `packages/npc-settings`：无宿主、无 React 依赖的数据契约、字段校验、版本及乐观锁；SQLite 驱动适配单独入口。
- `packages/npc-settings-react`：根据字段目录生成角色编辑表单，不认识角色 ID、技能名称和营地动作。React 是明确的 UI 依赖，其他引擎复用数据层并实现自己的 UI。
- `src/integrations/storage`：浏览器 IndexedDB 适配。SQLite 适配由宿主注入连接，不能把浏览器内存 SQLite 冒充持久存储。
- `src/games/camp/settings`：字段目录、默认值、NPC 初始化、工作技能映射、设置页面装配。

## 数据
版本 1 文档含 gameId、schemaVersion、按角色 ID 的数值表。角色目录和字段目录由游戏注册，核心不能包含 azhuang、wood 等营地专用字段。
每次保存整份文档，数据库保存单调递增 revision。以 expectedRevision 原子比较后写入，防止多个页面编辑相互覆盖。不同 gameId 隔离。未知角色、未知字段、缺项、NaN、Infinity、越界、步长错误及未来版本均拒绝，不悄悄截断。

## 运行集成
当前网页采用 IndexedDB；SQLite 适配器支持参数化 SQL、事务、修订号比较，并使用真实 SQLite 做合同测试。设置页支持滑块+数值、当前角色恢复默认、全部恢复默认、JSON 导入导出、取消与错误提示。新开局必须等设置读取完成；读取失败保留旧存档，允许用户明确选择默认值启动。
自定义 NPC 保存经过校验的初始模板快照，全默认角色保持原结构。九项人格用于心智；用户修改的勇气/勤奋/共情维度映射到 MLP，未修改的维度保留旧投影，避免只改体力也改变策略。有效新档保留已保存的模型投影，不在加载时重新计算。技能级别 0..100，默认 50，对应工作速度倍率 0.5..1.5；只影响相应真实任务耗时，不直接制造资源、不加速携带物资的返送、不改变休息或进食。
剧情场景状态在初始化模板之后按明确规则应用：冲突场景继续保留指定的饥饿及初始命令，界面解释覆盖关系。

## 验收
校验边界、跨游戏目录、SQLite 重新打开、CAS 冲突、损坏存储；五角色独立保存；新游戏应用而旧档不变；技能影响真实任务耗时且中性值保持旧行为；人物表达读取自定义人格；手机窄屏、键盘、取消、导入错误、持久化刷新。
