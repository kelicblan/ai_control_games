# SQLite 存档与持续世界

## 运行

需要 Node.js 24+。`npm run dev`、`npm run preview` 自动启动独立本机世界服务，默认监听 `127.0.0.1:18081`，通过同源 `/game-api` 代理访问。服务以独立隐藏进程运行，关闭网页或 Vite 不会关闭它。也可用 `npm run world` 单独运行，不要重复启动同一端口。

生产部署必须同时运行世界服务并代理 `/game-api`；仅发布 `dist/` 静态文件不能继续游玩。Steam 尚未打包接入；届时应将数据库放在用户数据目录，由桌面启动器管理服务生命周期。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `CAMP_WORLD_DB` | 项目根目录 `data/world.sqlite` | 数据库路径；桌面版应使用用户数据目录绝对路径 |
| `CAMP_WORLD_PORT` | `18081` | 服务端口；Vite 和服务必须一致 |

日志为 `data/world-service.log`。数据库、WAL 和日志不进入 Git。持久 HttpOnly Cookie 识别本机玩家；不同浏览器、清除 Cookie、切换 localhost/127.0.0.1 或域名会创建不同身份，旧世界仍在数据库中。本阶段没有账号/Steam 身份同步或云存档。

## 世界推进和暂停

- 服务端统一执行 100ms 固定步长模拟，使用原有规则/MLP 决策、随机数和 NPC 心智逻辑。网页发送指令并读取状态。
- 切页只停止音效和浏览器台词生成，不暂停游戏。关闭页面后世界继续推进，到原有 240 模拟秒的胜利/失败结算为止，不自动开始下一局。
- 手动暂停持久化，重开网页、重启服务都仍暂停。对话/设置窗口的临时暂停由所属页面续租；页面消失或被冻结超过 3 秒后到期恢复。
- 服务崩溃、电脑关机期间没有进程运行；重启后从已提交检查点按保存速度补算离线时间。分批执行避免阻塞请求，补算期间暂缓操作。系统时间倒退不会倒放世界。
- LLM 字幕仍经网页模型/原生模型接线生成；没有网页时使用行为引擎即时回应。NPC 行为、记忆、关系、物资和承诺照常演化。字幕提交只能改对应人物和对话行。

## 保存与恢复

SQLite 使用 WAL、`synchronous=FULL` 和事务。状态、时间、速度、暂停、修订和操作 UUID 一起提交。正常运行约每秒保存，关键操作提交成功才返回；页面显示最近成功落库时间。

每个玩家保留最近 20 个正常快照。每份校验 SHA-256、版本和游戏结构；最新无效时回退上一份，从其自身检查点补算。损坏原记录标为隔离，正常清理不会删除。全坏或版本不支持时禁止覆盖并显示错误；SQLite 文件本身损坏需从备份恢复。

首次连接且数据库无存档时，尝试迁入该站点原有 localStorage 存档，始终保留浏览器原始数据。已有数据库世界时不重复迁入。旧页面与重复操作不能覆盖新修订或重复消耗物资。

自动推进最多约 1 秒尚未提交；崩溃后重新补算，已确认操作已经落库。磁盘写满等错误会显示保存异常，无法写入期间的新操作不能保证保留。

备份：停止独立世界服务后，将 `world.sqlite` 及仍存在的 `world.sqlite-wal`、`world.sqlite-shm` 复制到新备份目录；不要在运行中只复制主文件。恢复前保留当前文件，再在服务停止时替换整组文件。不要删除数据库来解决连接错误。

## 验收

`npx vitest run tests/world.test.ts tests/world-http.test.ts tests/world-client.test.ts` 覆盖无客户端推进、真实进程强杀/重启与 SQLite 落盘、规则补算一致、MLP、速度/暂停/租约、长时间补算、时钟倒退、快照回退、全坏/新版本拒绝覆盖、操作去重和旧档迁移。

页面实测：离开时剩余 2:16；离开期间继续运行，重开显示“继续上一次旅程 4 分 0 秒”，恢复进入“天亮了，我们都在。”结算（评分 4674）。截图：`screenshots/sqlite-world-restored.png`。
