# 对话保存与离线补算稳定性修复

2026-10-15，针对“对话生成或保存失败：正在补算离线世界，请稍后再操作”。

## 根因与修复

- `WorldRuntime.advance` 按批次开始时的时间推进，但旧 `read/mutate/tick` 在计算或 SQLite 保存后重新取时间判断积压。正常处理超过一个 100ms 步长也会被误判为离线补算，阻止操作、对话保存和认知调度。
- 对话已经生成后，`dialogue-result` 仍被通用补算保护拒绝。客户端虽然保留生成结果，但两次重试耗尽仍无法发布。
- 现在以本批次固定目标判断是否还有未处理步骤；不可变对话记录允许在真正补算期间保存。世界 scope、版本冲突、内容校验、事务和幂等检查保留；改变模拟状态的操作仍受真正积压保护。

## 验证

- 三个回归测试修复前均复现失败：慢保存误判、计算跨 tick 后误拒操作、离线补算中保存回复失败；修复后通过。
- 9 个相关测试文件共 62 个不同测试通过，覆盖世界运行时、HTTP、客户端、对话会话、认知绑定/调度、领主输入、重置及持续世界。
- HTTP 测试使用独立临时 SQLite 和真实服务进程：十分钟离线积压尚未处理完时保存成功；硬终止、重启、重复请求后记录仍只有一条。
- `npx tsc -b` 通过。未运行全仓库测试或浏览器模型推理 E2E；上述 HTTP 回复是测试输入，不代表模型生成质量验证。
