# 营地策略网络 v1

## 这个模型是什么

这是一个在本仓库中实际训练、随游戏一起交付的专用多层感知机（MLP）。它读取营地状态，输出八种行动与五种情绪类别。浏览器加载二进制权重后，用本地 JavaScript 执行矩阵运算，不调用推理服务器，也不需要 API 密钥。

**它不是 LLM，不理解自由中文指令，也没有通过微调获得语言、长期记忆或复杂社会推理能力。** 中文台词由游戏表现层根据状态和类别组织，不是模型生成的文字。人格、资源、关系数值与世界状态由模拟器保存；模型根据这些显式输入选择行动。

模型的用途是让这个游戏可观察、可对照地验证：一个真实学习的极小网络，能否模仿受约束的角色决策。规则模式使用训练时的同一个教师，不刻意降低规则能力，不声称神经网络优于教师。

## 模型与文件

| 项目 | 实际值 |
| --- | --- |
| 网络 | 36 输入 → 64 ReLU → 48 ReLU → 独立的 8 行动、5 情绪输出 |
| 可训练参数 | 6,125 |
| 精度 | Float32，小端存储；未量化 |
| 权重文件 | `public/models/policy.f32` |
| 权重文件大小 | **24,500 字节**，约 23.93 KiB |
| 清单 | `public/models/manifest.json`，含特征顺序、张量布局、训练信息与评估结果 |
| 对照样例 | `public/models/parity-fixtures.json`；只用于验证，不是推理时查表 |
| 权重 SHA-256 | `d919ed6421f1c222ca5d9179090673e9fb2f34a7b8e9c0b978b10632fa6d8c4b` |
| 外部预训练权重 | 无 |

24,500 字节仅指权重文件。运行还需要清单、JavaScript 对象、临时激活和浏览器运行时；游戏画面、音频及其他资产另计。此数值不是下载整款游戏的体积，也不是进程内存或峰值 RAM。

本次产物没有单独指定权重许可证，不应把其他开源模型的协议套用到这里。数据由本仓库脚本合成，不包含第三方预训练模型权重。

## 输入和输出契约

特征数组由 `src/game/observation.ts` 的 `FEATURE_NAMES` 定义，全部归一化、截断到 `[0, 1]`。训练脚本、模型清单与加载器验证同一个顺序。

| 索引 | 输入 |
| --- | --- |
| 0–5 | 饥饿、体力、健康、士气、恐惧、信任；除以 100。饥饿越高表示越饿 |
| 6–8 | 勇敢、勤勉、同理心 |
| 9–13 | 木材 / 30、食物 / 15、火势 / 100、危险 / 100、已过时间 / 总时长 |
| 14–16 | 下雨、刮风、自身受伤标记 |
| 17–18 | 存活队友最低健康 / 100、需要帮助的队友数 / 2 |
| 19–22 | 其他采木、采食、添柴、互助工人数 / 2 |
| 23–30 | 玩家命令的八项 one-hot；没有命令时全零 |
| 31–32 | 木材优先、食物优先标记 |
| 33–35 | 距营地距离 / 100、携带木材 / 6、携带食物 / 4 |

行动顺序为 `wood, food, fire, eat, rest, help, camp, explore`；情绪顺序为 `calm, happy, worried, annoyed, caring`。

游戏另行传入 `allowed` 合法行动列表。模型和规则都会屏蔽不合法行动，再选择剩余最高分行动。返回的 `scores` 是经过掩码的 softmax 偏好分数，不是校准过的成功概率。寻路、资源交易、任务执行、伤害、存活判定与行动容量均由模拟器处理。

## 训练方法与数据

运行 `python scripts/train_policy.py` 或 `npm run train` 即可重建。训练只依赖 Python 与 NumPy；本次使用 NumPy 2.3.5、单线程 BLAS、种子 **20261012**。

- 64,000 个合成训练状态，8,000 个独立验证状态。
- 60 个 epoch，batch size 512，Adam，初始学习率 0.0025，线性衰减。
- 对两个输出头回归教师效用值；动作损失权重为 0.35，情绪损失权重为 1。
- 根据验证集动作/情绪一致率及动作误差选择 checkpoint；本次为 epoch 59。
- 留出测试和分布偏移测试均不用于梯度更新或 checkpoint 选择。

训练包含随机、相关状态，以及饥饿、疲劳、高危险、火势紧急、命令、队友受伤、良好士气、临近天亮和低信任冲突等明确状态组。人格在三类原型附近采样，并加入扰动。命令由独立特征表示，不能绕过动作合法性。

在同一环境的独立临时目录重跑默认训练命令后，`policy.f32`、`manifest.json`、`parity-fixtures.json` 三个文件均逐字节一致。跨 NumPy/BLAS 版本或硬件时，浮点训练的位级一致性仍需另行验证。

教师在 `scripts/train_policy.py` 与 `src/ai/teacher.ts` 中有等价实现：资源短缺、饥饿和疲劳影响行动效用；危险与距营地距离提升回营效用；需要帮助的队友和同理心影响互助；命令的作用受信任等状态调节；最后阶段强烈抑制外出采集和探索。这些偏好来自人工设计，网络学习的是这些偏好的近似。

## 已测评估结果

下面是对**合成教师标签的一致率**，不是人类偏好得分、真实世界理解能力或游戏胜率。

| 数据集 | 状态数 | 行动一致率 | 情绪一致率 |
| --- | ---: | ---: | ---: |
| 独立常规留出集 | 12,000 | 96.6833% | 96.5917% |
| 七类分层复合危机 | 8,000 | 95.9750% | 98.4875% |

七类危机包括：临近天亮的暴雨加外出命令、饥饿加工作命令、疲劳加工作命令、大风中火势很低、两名队友需要帮助但被要求休息、食物耗尽且饥饿、木材耗尽且火势很低。各类接近等量，避免只测危险状态导致“全部回营”也能获得虚高分数。

常规留出集八种行动都有样本，各行动一致率约 94.8%–97.7%。复合危机中休息为 **88.57%**、互助为 **86.03%**，说明命令和需求冲突时仍存在明显近似误差；该危机集没有以探索为教师最优解的样本。完整分母与混淆矩阵写在模型清单中，不能只看总体准确率。

### 数值一致性与关键行为

46 个独立 NumPy 导出的参考状态包含 14 个具名案例和 32 个未经手选的随机案例。JavaScript 与 NumPy 的最大输出误差为：行动约 `5.01e-6`，情绪约 `1.61e-6`。全部参考状态的模型行动与情绪类别一致；JavaScript 规则教师与 Python 教师的效用数值也按容差验证。

关键案例实际产生：饿了吃饭、疲劳休息、高危险回营、正常状态响应采木命令、极度疲劳时拒绝采木、临近结束回营、同理心较高时帮助受伤队友。模型同时输出了五种情绪类别。测试还检查唯一合法动作、输入维度、归一化范围、NaN、错误版本、张量错位、截断文件和 SHA-256 损坏。

### 速度与边界

当前开发容器的 Node.js v24.19.0 / Linux x64，预热 2,000 次后，对 20,000 次同步推理实测：平均 **0.02091 ms**，中位数 **0.01366 ms**，P95 **0.03309 ms**，最大 **1.60083 ms**。该测量包含特征验证、网络前向计算、动作掩码与结果构建。

这是一个运行时、一个环境的测量，不能用来保证手机浏览器速度或整帧渲染性能。本次未测手机峰值 RAM。三名 NPC 共用权重、各自传入状态；游戏会错开决策。网络很小，因此本版使用同步推理；扩展网络或增加 NPC 数量后应重新测量。

## 加载失败与降级

`loadPolicy()` 只加载静态清单和二进制文件，校验版本、输入顺序、输出顺序、网络形状、字节数、有限权重与 SHA-256；出错会抛出可显示的错误，不伪装成模型成功。完整性校验需要支持 Web Crypto 的安全页面环境。

`inferPolicy()` 不会在内部悄悄改用规则。模拟器如需容错，必须把该次决策标记为 `fallback`，并保存原因。模型加载失败时，界面应让用户明确选择规则模式。

## 限制与后续工作

模型可能在接近并列的选择、复合需求或训练分布外状态上偏离教师。固定 36 个输入会丢失长历史和更复杂的关系信息；网络的情绪标签不代表角色存在内在情感体验。当前结果没有证明复杂社会行为、自然语言理解或规则之外的策略优势。

当前完整回合的正式评估使用与界面一致的 **0.1 秒固定步长**，共 14 局，详见[评估报告](evaluation.md)与[原始结果](evaluation-results.json)。浏览器整局、离线重载和故障处理另见[交付验证](validation.md)。

### 早期开发诊断（不代表当前版本）

早期引擎快照下，三个种子、三种难度、两种策略的 18 局无人指挥测试全部获胜，这暴露的是当时玩法压力过小，不能当作当前或未来版本的稳定胜率。游戏平衡与事件变化后，应重新运行端到端评估，不通过弱化规则基线制造模型优势。

第二版平衡的针对性集成检查使用 `storm` 场景、种子 7、固定 `dt=0.25`：普通难度无人指挥时，模型于 229 秒灭火失败，规则撑到 240 秒；困难难度无人指挥时，模型于 184.25 秒失败，规则于 148.75 秒失败。两种策略均没有输出降级决策。这说明很高的单步教师一致率仍可能累积成不同终局，不能代替实际玩法验证。

同一困难暴雨场景中，每 10 秒按资源状态通过真实游戏命令安排采木、添柴、分食，并在 210 秒全队召回，模型经 31 次输入后在 240 秒获胜，三人健康约为 `[98.22, 100, 100]`，火量约 19.43，仍为零降级决策。这是一个种子的可救援验证，不是全种子胜率保证；比较时需要保持场景、种子、模拟步长和玩家控制器一致。
