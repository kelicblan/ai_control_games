# 营地天气策略网络 v2

## 这个模型是什么

这是一个在本仓库中实际训练、随游戏一起交付的专用多层感知机（MLP）。它读取营地状态，输出八种行动与五种情绪类别。浏览器加载二进制权重后，用本地 JavaScript 执行矩阵运算，不调用推理服务器，也不需要 API 密钥。

**它不是 LLM，不理解自由中文指令，也没有通过微调获得语言、长期记忆或复杂社会推理能力。** 中文台词由游戏表现层根据状态和类别组织，是模板文字。人格、资源、关系、天气与身体状态由模拟器保存；模型根据显式输入选择行动。

模型用于观察一个真实学习的小网络如何模仿受约束的角色决策。规则模式直接使用训练时的同一个教师，不刻意降低规则能力；当前结果不证明神经网络优于教师。天气动画、物理后果和台词本身都不是模型推理的证据，应检查该次实际输入、合法动作、分数与执行结果。

## 输入和输出契约

特征数组由 `src/game/observation.ts` 的 `FEATURE_NAMES` 定义，全部归一化、截断到 `[0, 1]`。训练脚本、模型清单与加载器验证同一个顺序。v2 保留原有 36 个特征的位置，将原先雨、风的布尔输入改为连续强度，并在末尾增加五项天气与遮蔽信息；旧权重不能用于新观测。

| 索引 | 名称与单位 |
| --- | --- |
| 0–5 | 饥饿、体力、健康、士气、恐惧、信任；除以 100。饥饿越高表示越饿 |
| 6–8 | 勇敢、勤勉、同理心 |
| 9–13 | 木材 / 30、食物 / 15、火势 / 100、危险 / 100、已过时间 / 总时长 |
| 14–15 | `rainIntensity`、`windStrength`，连续强度 `[0, 1]` |
| 16 | 自身受伤标记 |
| 17–18 | 存活队友最低健康 / 100、需要帮助的队友数 / 2 |
| 19–22 | 其他采木、采食、添柴、互助工人数 / 2 |
| 23–30 | 玩家命令的八项 one-hot；没有命令时全零 |
| 31–32 | 木材优先、食物优先标记 |
| 33–35 | 距营地距离 / 100、携带木材 / 6、携带食物 / 4 |
| 36 | `stormRisk`：模拟器的连续雷暴风险 `[0, 1]`，不是一次闪电的发生概率 |
| 37 | `wetness`：角色湿透程度 / 100 |
| 38 | `exposure`：当前暴露程度；0 为完全受保护，1 为完全暴露 |
| 39 | `shelterIntegrity`：雨棚完好程度 / 100 |
| 40 | `shelterDistance`：当前位置距雨棚覆盖边界的距离 / 100；已在覆盖区内为 0 |

行动顺序为 `wood, food, fire, eat, rest, help, camp, explore`；情绪顺序为 `calm, happy, worried, annoyed, caring`。`rest` 表示到休息区恢复，在风雨中可进入帐篷前的雨棚；`camp` 表示返回篝火附近。最终目的地、携带物资的返程以及实际遮蔽效果由模拟器决定。

游戏另行传入 `allowed` 合法行动列表。模型和规则都会屏蔽不可执行的行动，再选择剩余最高分行动。天气本身不会把采集或探索从列表中删除：在同一合法动作集合中，天气可以改变网络分数和最高分动作。返回的 `scores` 是经过掩码的 softmax 偏好分数，不是校准过的成功概率。寻路、资源交易、任务执行、伤害、存活判定与工作容量由模拟器处理。

### 供后续语言模型适配的共同观测

真实的 `getObservation()` 还提供结构化 `context`：同一次天气快照、角色的位置和健康/体力/饥饿/恐惧、木材/食物/火势，以及存活同伴的位置、健康和行动。该对象中的湿透程度、雨棚完好程度和距离保留模拟器的原始单位；网络向量在对应索引中归一化这些相同数值。

观测复制位置和天气字段，适配器读取或修改自己的对象不会改写模拟世界。现有 MLP 只读取有序向量，未来适配器可以读取该结构化视图和同一 `allowed` 列表；**本次没有接入 LLM，没有调用远程语言服务。** 结构化字段不是神经网络生成的解释，也不提供模型未观察到的隐藏事件计划。

## 训练方法与数据

运行 `python scripts/train_policy.py` 或 `npm run train` 即可重建。训练只依赖 Python 与 NumPy；本次使用 NumPy **2.3.5**、单线程 BLAS、种子 **20261012**。

- 64,000 个合成训练状态，8,000 个独立验证状态。
- 60 个 epoch，batch size 512，Adam，初始学习率 0.0025，线性衰减。
- 对两个输出头回归教师效用值；动作损失权重为 0.35，情绪损失权重为 1。
- 根据验证集动作/情绪一致率及动作误差选择 checkpoint；本次为 **epoch 54**。
- 留出测试和分布偏移测试均不用于梯度更新或 checkpoint 选择。
- 数据划分种子为：训练 `20261022`、验证 `20261032`、留出 `20261042`、复合危机 `20261052`。

训练既包含随机组合，也包含饥饿、疲劳、高危险、火势紧急、命令、队友受伤、良好士气、临近天亮和低信任冲突等状态组。天气包括晴朗、雨、风、雷暴及连续强度；湿透程度可在雨停后或进入雨棚后保留。遮蔽、雨棚损坏、距遮蔽区距离与身体状态共同进入观测。新增明确状态组覆盖谨慎角色在外遇到雷暴、勇敢角色面对低火势雷暴、浑身湿透且靠近雨棚、雨棚受损等情形。

教师在 `scripts/train_policy.py` 与 `src/ai/teacher.ts` 中有等价实现。天气和湿透会提高室外工作的代价；雷暴、当前暴露、人格、湿透程度和雨棚可用程度共同影响休息效用。雨、风会提高保护篝火的效用，低火势和勇敢程度可以让添柴胜过躲雨。饥饿、疲劳、危险、同伴需求、命令、资源短缺和最后返营窗口继续与天气竞争。**这些偏好由人工设计；网络学习它们的近似，没有通过在线游戏自行发现天气规律。**

固定种子和线程设置使训练过程可重跑；跨 NumPy/BLAS 版本或硬件的浮点位级一致性需要另行验证。具名验证案例不用于训练或 checkpoint 选择。

## 已测评估结果

下面是对**合成教师标签的一致率**，不是人类偏好得分、天气理解能力或整局游戏胜率。

| 数据集 | 状态数 | 行动一致率 | 情绪一致率 |
| --- | ---: | ---: | ---: |
| 独立常规留出集 | 12,000 | **95.1000%** | **95.5833%** |
| 十类分层复合危机 | 8,000 | **98.0500%** | **97.2500%** |

十类危机接近等量采样：临近结束的雷暴加外出命令、饥饿加工作命令、疲劳加工作命令、大风中火势很低、两名队友需要帮助但被要求休息、食物耗尽且饥饿、木材耗尽且火势很低、暴露在雷暴中的谨慎角色、雷暴中面对临界火势的勇敢角色、浑身湿透且靠近雨棚。该分布与常规留出集不同，因此不能把两者百分比直接解释为任务难度的排序。

| 行动 | 常规留出样本数 | 常规一致率 | 危机样本数 | 危机一致率 |
| --- | ---: | ---: | ---: | ---: |
| 采木 | 361 | 92.24% | 906 | 98.57% |
| 采食 | 499 | 94.79% | 882 | 99.43% |
| 添柴 | 1,680 | 95.30% | 1,672 | 99.52% |
| 进食 | 800 | 94.63% | 683 | 97.80% |
| 休息 | 4,012 | 95.39% | 2,242 | 96.65% |
| 互助 | 666 | 97.00% | 814 | 95.82% |
| 回营 | 3,620 | 94.70% | 800 | 99.38% |
| 探索 | 362 | 95.86% | 1 | 0.00% |

危机集只有 **1 个**教师选择探索的状态，且模型没有答对；它不足以评价危机下的探索表现。常规集中“烦躁”的情绪一致率为 **87.60%**，低于总体情绪一致率。完整分母与混淆矩阵保存在模型清单中，应结合类别分布阅读总体分数。

### 数值一致性与天气行为

54 个独立 NumPy 导出的参考状态包含 22 个具名案例和 32 个未经手选的随机案例。在 Node.js v24.19.0 的 JavaScript 推理器中，最大输出误差为：行动 **`7.63e-6`**，情绪 **`1.26e-6`**。测试逐项比较 logits、动作、情绪，并验证 JavaScript 教师与 Python 教师效用值一致。

`tests/weather-policy.test.ts` 直接加载交付权重，在保持合法动作列表不变的成对输入上检查：

- 谨慎角色在晴朗时采食，仅改变雨、风、雷暴风险后选择休息躲雨。
- 同一场雷暴、同样较低火势下，仅改变勇敢程度：谨慎角色选择休息，勇敢角色选择添柴。
- 湿透提高休息偏好，火势紧急时仍可以选择添柴。
- 单独改变雨、风或雷暴风险，都能改变真实网络 logits。
- 连续天气输入产生有限 logits、合法动作和归一化分数。
- 原始结构化天气与 41 维归一化观测保持对应；天气变化不会通过硬掩码禁止采集。

这些是固定状态的数值和行为验证。它们不说明每次遇雨都应躲雨，也不构成某次自然游戏决策的完整因果解释。环境和角色状态同时变化时，需要读取那次实际记录。

其余测试继续覆盖饥饿吃饭、疲劳休息、高危险回营、响应和拒绝命令、最后返营窗口、同伴互助、唯一合法动作、非法维度、归一化范围、NaN、错误版本、张量错位、截断文件和 SHA-256 损坏。

## 加载、运行与降级

`loadPolicy()` 只加载静态清单和二进制文件，校验格式版本、观测版本、输入与输出顺序、网络形状、字节数、有限权重与 SHA-256。完整性校验需要支持 Web Crypto 的安全页面环境。旧的 36 维模型不能伪装成新天气模型加载。

`inferPolicy()` 不会在内部悄悄改用规则。模拟器如需容错，必须把该次决策标记为 `fallback` 并保存原因；只有真正通过神经网络推理的决策才标记为 `model`。台词和天气表现仍是模拟器模板与渲染结果。

三名 NPC 共用权重，各自传入状态。网络很小，本版继续采用同步推理，决策面板记录每次实际耗时。本卡不沿用旧 36 维模型的速度数字，也不保证手机浏览器的帧率、推理时延或峰值 RAM；扩展网络或角色数量后需要重新测量。

## 限制与后续工作

模型可能在接近并列的选择、复合需求和训练分布外状态上偏离教师。41 个标量会丢失长历史、更复杂的空间结构、关系细节以及自然语言含义；情绪标签不代表角色存在内在情感体验。雨棚和身体湿透的物理效果、天气事件频率以及每次重新决策的时机均由模拟器规定，网络不能修改这些机制。

本卡的准确率只针对当前 v2 权重的离线合成状态。完整回合结果需要同时固定权重、引擎版本、种子、场景、难度、模拟步长和玩家输入，详见仓库的[评估报告](evaluation.md)。早期 36 维权重或旧天气引擎下的胜负与救援记录，不应作为本次天气版本的通过证据或胜率保证。
