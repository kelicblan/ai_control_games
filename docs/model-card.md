# 村寨生存库存策略网络 v3

这是本仓库用合成教师数据训练的 MLP，在本地输出八种行动偏好与五种情绪。它不生成语言；固定台词和可选语言模型对话通过独立的村寨上下文生成。世界状态、库存、寻路、采集和吃饭由确定性模拟器负责。

## 输入、行动与安全边界

`src/games/camp/simulation/observation.ts` 和清单定义特征顺序。v3 保留 v2 的 41 项位置，追加 `foodReserveRatio`、`projectedFoodRatio`、`foodDispatchNeeded`，取值截断到 `[0,1]`。旧版决策历史仍可读取，旧权重不能解释新观测。

八个输出为 wood、food、fire、eat、rest、help、camp、explore；五个情绪为 calm、happy、worried、annoyed、caring。fire 保留兼容输出位置，但当前世界禁止将装饰篝火作为生存任务。输出是经过合法动作掩码的相对偏好，不是成功概率。

生存规则从活人数量、实际饥饿消耗和仓库到野外的往返时间计算最低库存和补给目标，计入实际搬运、有效采集承诺和待领餐份额。低库存时优先补给，库存回升后持续补到目标线；死亡、失效或枯竭目标不虚算产量。健康、体力、威胁、关门、明确移动指令等边界仍有效。模拟器可以覆盖网络选择，因此动作证据应同时检查输入、网络分数、仲裁原因及真实执行。

训练覆盖九种现有人格原型和村寨长距离。对话只能描述真实任务阶段、目的地、仓库、个人住房、广场及当前城门状态；没有练武、锻造任务，也不声称去帐篷避雨。语言模型不直接修改世界。

## 训练与离线指标

运行 `python scripts/train_policy.py`。默认随机种子 20261015，Adam，80 epochs，batch 512，选择第 73 epoch；训练 64,000、验证 8,000、独立留出 12,000、分布偏移 8,000 条样本。损失为 `0.35 * action MSE + emotion MSE`。

本次实际环境 Python 3.12.10、NumPy 2.5.3，BLAS 单线程；`requirements.txt` 固定本次 NumPy 版本，完整参数与拆分种子见清单。使用不同 NumPy/BLAS 版本不保证逐字节复现，需比较清单与 SHA。

| 样本组 | 行动准确率 | 情绪准确率 |
| --- | --- | --- |
| 验证集 | 96.8750% | 95.9250% |
| 留出集 | 96.8583% | 95.9667% |
| 分布偏移集 | 98.1000% | 96.3375% |

这些数值衡量对合成教师的模仿，不证明优于规则，也不保证任意局势都能存活。规则模式直接运行教师；生存规则本身仍须接受真实固定步长回放验证。

## 游戏验证与上线限制

执行 `npm run evaluate:survival -- --seeds=17,41,7 --seconds=1800 --output=docs/survival-model-normal-final.json`；困难模式加 `--difficulty=hard`。验收同时检查运行到指定时长、全员存活、状态有效、真实食物入库和领餐、预热后库存非零，以及连续低库存不超过 180 秒。

完整结果及未解决项见 [村寨 NPC 验证记录](validation-village-npc-alignment.md)。样本覆盖有限，关门、断绝资源或玩家强制阻止补给仍可能导致饥荒。已有存档迁移不赠送库存、不复活 NPC；只有新游戏按最低库存初始化。长期运行的世界服务必须重新启动后才加载新代码与模型。
