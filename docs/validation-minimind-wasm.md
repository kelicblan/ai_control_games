# MiniMind3 WASM 接入验证（2026-10-12）

本次取代旧 Python/DLL 台词服务；此前 `validation-minimind.md` 中的原生速度仅为历史记录。修改基于已合入五人社交的 main `faf3b31`。

## 实际路径

场景加载完成 → 同源静态 model.json / GGUF → Worker 校验 68,189,920 字节和 SHA-256 → 独立 CacheStorage 保存 → 已校验 Blob 交给 wllama → Worker 内 CPU WASM 推理 → 当前有效气泡或暂停对话记录。

依赖固定为 wllama / compat 3.8.1。默认 WASM 8,763,949 字节，兼容 WASM 16,005,007 字节；两者静态托管，不请求外部 CDN。使用单线程，不依赖 SharedArrayBuffer、COOP/COEP 或 WebGPU。模型 SHA-256 为 `c994601ed72cb24addd206ed28ee7e8cea0283081a0434947c4e1e7a6d2ce45e`。

删除 `npc_server.py`、旧服务测试和 HTTP smoke 脚本，移除 Vite `/npc-api` 代理。`dev:local` 只准备静态资源并启动 Vite，不启动 Python。旧的本机 8765 服务已停止；现有 5173 游戏进程保留，实际返回的 dialogue 模块使用 `minimindRuntime.generate`，不含 `npc-api`。

GGUF 不在 Service Worker 预缓存清单中。独立 `minimind-model-<sha256>` 缓存不受游戏版本缓存清理影响。无模型的构建生成 available=false 的静态清单，避免可选权重 404 污染游戏资源错误。

## 验证证据

- 新资产测试先因模块缺失失败，再实现并通过；覆盖完整校验后保存、无网络复用、损坏缓存替换、截断/同尺寸篡改拒绝和配额失败内存回退。
- Worker 协议测试覆盖共享加载、取消后持有占用直到确认、取消卡住后终止 Worker。台词测试覆盖加载就绪时重扫暂停对话，保留原有重开/状态变化/受伤/社交失效检查。提示词测试验证只保留当前人物显式上下文，约定状态不会被截掉。
- 真实 Chromium 中用实际 Q8 GGUF 完成 CPU WASM 推理，暂停的社交对话出现 MiniMind3 来源句子，安排按钮仍可用。
- 同一浏览器随后断网并重新加载页面，游戏、Worker、WASM 和模型均从各自本地缓存恢复，界面显示“已从本地缓存加载”，没有新的 GGUF 请求，也没有 `/npc-api` 请求或页面异常。
- 第一次真实浏览器脚本已完成推理，但重载后错误寻找新旅程按钮；修正为继续已有存档后完整通过。另一次静态 staging 在 Windows 替换已有打开文件时 rename 失败；改为校验并跳过相同目标，重新构建通过。
- 加载就绪的精确次数断言发现就绪事件和 prepare 完成各自重新扫描，导致同一句启动两次；移除重复清空，回归断言只启动一次。
- 慢下载时模拟时间及真实 MLP 决策继续推进；损坏模型保留即时台词，开关可独立使用。
- 最终 321 项单元测试通过，生产构建通过（保留原有大包提示）；40 个固定游戏/运行时资源加入离线预缓存，GGUF 单独缓存。
- 包含真实 WASM、冷/离线加载、天气、五人社交、两种移动尺寸及完整胜利/失败旅程的 11 项浏览器回归通过。最终构建另行复跑慢下载、损坏模型、无模型部署、真实 WASM/离线重载共 4 项通过。
- 新增无模型部署测试起初被 Service Worker 的真实可用清单覆盖了模拟清单，实际加载了模型，导致断言失败；隔离该模拟用例的 Service Worker 后单独复跑通过。

- 某次真实随机采样未通过内容检查，游戏正确保留模板，原先要求第一条必定生成的测试失败；验收改为最多四条正常交流中至少出现一条合格生成，不承诺每个输入都有模型回答。最终实测该项通过。
- 将生产静态清单临时设为 available=false 模拟无模型部署，三个便携资源回归全部通过；测试结束已恢复原清单。

## 尚未验证

当前仍使用动作/交流前缀后续写与启发式过滤。实际表达可能复述事实或不够自然，语义正确率和长期角色一致性没有验收；应继续用游戏语料微调。没有把 Windows 原生毫秒级耗时当作 WASM 延迟承诺。
