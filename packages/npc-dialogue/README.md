# 通用 NPC 对话包

本包只负责异步语言请求和文字编排，不依赖具体游戏、DOM、Node 或模型 SDK。
`DialoguePayload` 中的人物、动作和情绪都是不透明字符串；事实、私人意图、公开表达、双方历史分开传递。
游戏的动作执行和资源变化永远不能由语言返回值触发。

## 接入另一款游戏

1. 提供 `DialogueBridge<TTicket>`。`collect()` 从本游戏的状态生成候选；`isCurrent()` 检查人物意图、对话和世界版本；`commit()` 再次校验后同步发布字幕并返回写入后的版本。
2. 注入 `DialogueClock`。时间单位为真实毫秒，仅用于缓存、限频和后台超时，不推进模拟秒。`schedule()` 返回取消函数；`cancellation()` 返回由宿主实现的取消信号和取消方法。
3. 提供 `transport` 和 `validate`。宿主可先用 `buildDialoguePrompt()` 编排上下文，再交给任意模型；领域事实、语言和角色立场由该游戏的验证器检查。
4. 新游戏、读档或切换世界时调用 `reset()`。代际计数不会归零，即使新世界与旧世界的 ID、时间相同，也不会接受上一局的在途回答。
5. 人物永久离开世界时调用 `forgetActor(actorId)`，清理其版本、冷却、近期字幕、队列、缓存、公开状态和在途任务。`collect()` 只表示当前候选集，不能根据一次未入选推断人物已被销毁。
6. 角色立场改变时更新候选 `revision` 和语义 `key`，立即 `sync()`。`key` 包含心智和事实，避免缓存回放曾经礼貌、现在已经拒绝的回答。

`urgent` 候选可越过常规字幕冷却并最多重试两次“后端忙”；`allowRefill=false` 适用于不可提前猜测下一句的双方交流。缓存、最近五句去重、取消后的结果隔离都由同一调度器维护。宿主已经显示的即时表达应先出现，模型失败时保留它。

独立边界检查：`npx tsc -p packages/npc-dialogue/tsconfig.json`。
`tests/npc-dialogue.test.ts` 用餐厅服务员的不透明 ID 和动作验证在途拒绝与换世界隔离，不导入营地世界。

语言请求超过 8 秒会释放调度器的逻辑槽，即使 transport 不理会取消也不会卡住后续人物。底层推理后端仍必须独立管理物理资源占用；被取消的迟到结果无法穿过调度代际校验。
